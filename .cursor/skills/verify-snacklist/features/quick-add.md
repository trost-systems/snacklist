# Quick add

The add bar sits at the bottom of the list screen, right above the floating tab pill, with the hint „Was brauchst du?“ / "What do you need?". The field floats over the list with the rows' 16 px inset on both sides: the list scrolls on under it, and the list ends with room so its last row stops above the field (job 135). The whole band around the field, the gutters beside it included, counts as the field: a near miss opens the sheet and never ticks a row hidden under the field (e2e `add-sheet.spec.ts`). A mouse wheel or trackpad scroll over the band or the tab pill scrolls the list under them; a click still opens the field (job 159, e2e `add-sheet.spec.ts`). Typing into it, or tapping anywhere on it, opens the add sheet over a dimmed list (it shows no title and, since job 474, has no screen-reader name, which was a stop in front of the chips; on the web it is `[flt-semantics-identifier="add-sheet"]`). The sheet offers rows for what was typed, made on the device in the same frame as the key, also offline; the server's answer only fills in a category or store and moves no row (`qa-device-catalog`, `qa-stable-rows`): first the line itself as typed („Wie getippt“), then things the household bought before, other packs, kinds, sizes and brands, and words from the catalogue. Each row starts with the item's emoji (🔁 for every „Wieder fällig“ row). Enter takes the first row, a tap takes any row. After an add screen readers hear „<Name> hinzugefügt“ / "<Name> added" (job 474), the field empties, the cursor stays, and one row of chips shows the added item's amount, store and details, each changed with one tap and saved at once; there is no „✓ Hinzugefügt“ note and no „Rückgängig“, and no category chip (`qa-compact`, `qa-compact-chips`, `qa-hide-categories`: `add-sheet-compact` and `hide-categories` are full since 2026-11-22). The sheet has no ✕: its only „Schließen“ is the grab handle, and it closes with a tap beside it, a swipe down, Escape or Enter in the empty field (`qa-compact-close`). Behind it the list shows only the last two adds (`qa-compact-behind`); internal installs with `add-ae2-list-peeks` keep the whole list in view instead (`qa-ae2-peeks`). With the field empty the sheet offers what is due again. The added note with „Rückgängig“, the ✕ and the category chip belong to builds without those flags (`qa-added`, `qa-added-details`, `qa-chips`).

## Sub-features

- `qa-autofocus` the cursor is in the add bar when the list opens, on desktop and web; phones wait for a tap. The bar is one rounded field with the ✕ while text is typed and, on phones, the microphone; nothing sits left of the field (the "+" disc went in job 78).
- `qa-sheet` the sheet opens on the first keystroke or a tap on the bar, the field or the padding around it (the padding focuses the field too, and takes text dictated into it). On the users' build its top is only the grab handle, named „Schließen“ / "Close" (`qa-compact`); without `add-sheet-compact` (`VH_FLAGS_OFF=add-sheet-compact`) its first line holds a ✕ button named „Schließen“ (tooltip the same); under it the rows. With `add-feedback-list` off (a build without it, or a new install before PostHog's first answer) that line also holds the two chips of `qa-chips`. There is no title: adding happens on a row or with Enter. While it is open the tab pill slides away and the band shows the line „Antippen fügt hinzu · ↵ nimmt den ersten Vorschlag“ / "Tap to add · ↵ takes the first suggestion".
- `qa-rows` each row is one button named "<quantity> <name>, <source>, <brand>, <detail…>, <store>" (empty parts are left out; a bare count reads "2×", a count with unit reads "2 l", a quantity of 1 is not shown). Sources: „Wie getippt“ / "As typed", „Schon mal gekauft“ / "Bought before", „Andere Packung“ / "Other pack", „Andere Sorte“ / "Other kind", „Andere Größe“ / "Other size", „Andere Marke“ / "Other brand", „Aus dem Katalog“ / "From the catalog", „Wieder fällig“ / "Due again", „Zuletzt verwendet“ / "Recently used". While text is typed the first row is highlighted and carries a return-key glyph (it is what Enter takes; the compact sheet, `qa-compact`, only tints it, with no glyph since #600); with the field empty no row has them, since Enter then adds nothing.
- `qa-matching` what the server offers for the typed text (at most 8 rows, no row twice, asked about 120 ms after the last keystroke; the device shows the same rows at each key before that, `qa-device-catalog`): the typed line, read into name, brand, details and quantity (always first); up to 3 „Schon mal gekauft“ rows, the household's items from the last year whose name matches the typed name (2 or more letters), with their old brand, details and quantity (a quantity typed now wins); up to 2 „Andere Packung“ and up to 2 „Andere Sorte“ rows made from details bought before with the same name ("Big Pack", "laktosefrei"); 2 „Andere Größe“ rows when a "Größe n" is typed (n+1, n−1, between 1 and 8); up to 3 „Andere Marke“ rows (brands bought before with that name, then known brands of that product); up to 3 „Aus dem Katalog“ rows, dictionary words that match the LAST typed word (2 or more letters). A name matches, best first: the same name; it starts with the typed text; it has the typed text inside, from 4 letters („milch“ finds Hafermilch); or it is a typo of it, from 3 letters, with the same first letter and at most one wrong, missing or extra letter up to 5 letters, two from 6 („Hafermlch“, „Tomatn“). Under 3 letters only the start counts. Within a source exact and start matches come newest first (history) or shortest first (catalogue), inside-word and typo matches most similar first. Rows whose item is already open on the list are dropped, except the typed row.
- `qa-enter` Enter (also numpad Enter) adds the first row and keeps the cursor for the next item. The sheet stays open. Items can be added one after another by Enter without a click in Chrome, Safari and Firefox; on web the field's input keeps its focus the whole time (job 210: Firefox used to drop it about 80 ms after an Enter; e2e `wasm-boot.spec.ts` in the chromium, webkit and firefox projects). If the rows have not arrived yet Enter waits for them (up to 3 s, then falls back to the line parsed on the device); a close while it waits cancels it, and nothing is added (job 76).
- `qa-quantity` a leading amount becomes the quantity: "2 Äpfel" gives Äpfel with 2, shown "2× Äpfel"; "2 l Milch" gives Milch 2 l; "6x Eier" gives 6; "500 g Hack" and "Hack 500 g" both give 500 g; number words one to twelve count too, German and English ("zwei Gurken", "two apples", "eine Packung Eier"; "ein halbes Brot" gives 1/2; "anderthalb Liter Milch" gives 1,5 Liter), except at the start of a name like „Drei Glocken“, „Seven Up“, „Four Roses“ or „Elf Bar“ (job 104, `supabase/tests/number_words.tsv`); "6 x 1,5 l Wasser" stays one multipack token "6x1,5l". A trailing amount with a unit counts ("Hack 500 g"); a trailing count works as "Karotten x2" or "Karotten 2x", and a bare number or number word at the end ("Karotten 2", "Gurken zwei", "carrots two"; never „ein“, „eine“, „einen“, „einer“) is the quantity only when it is 1 to 20, does not follow a size or unit word (Größe, Nr., Stufe, size, mAh, ml …) or touch letters, and the rest is a word the dictionary knows or a name the household had before (job 61, `supabase/tests/quantity_parse.tsv`): "Vitamin D3", "7up" and "Büroklammern 100" keep their number in the name, and "Windeln Größe 4" gives Windeln with the detail "Größe 4" and no quantity. The same rules hold offline, online and in MCP (job 104); said (Siri, Alexa, dictation), a count after the item is the quantity unless it follows a size word (Größe, Typ, Nr., Stufe, Klasse): „Gurken zwei“ is 2 Gurken, „Windeln Größe 4“ stays whole (job 89). The row shows the quantity after the name, "Karotten · 2" (its accessible name puts it first: `2× Karotten, Wie getippt`, driven 2026-11-04); a row tapped while the rows for the new text are still loading takes the quantity typed now. Units include kg, g, l, ml, cl, Stück, Packung, Dose, Flasche, Bund, Becher, Glas, Tüte, Beutel, Netz, Kiste, Kasten, Rolle, Tafel, Stange and more.
- `qa-details` brand, details and store are read out of the typed line: "Windeln Pampers Größe 3" gives the row „Windeln, Wie getippt, Pampers, Größe 3, dm“ (a drugstore item or the brand's own store picks dm; a remembered store for the name wins).
- `qa-tap-row` a tap on any row adds it with every field it shows (quantity, brand, details, store, category) and keeps the cursor in the field.
- `qa-chips` (flag-off sheet only: `VH_FLAGS_FULL=0`, the e2e specs, or a new install before PostHog's first answer; users set the store after the add in `qa-compact-chips`) until the user picks, both chips show Snacklist's pick in muted text with a circled "A" mark where their icon goes: the store the rows decide, or just „Laden“ / "Store" when none is known; the category guess, or „Kategorie“ / "Category". Their accessible names say it: „Laden: automatisch“ / "Store: automatic", „Laden: automatisch, dm“ / "Store: automatic, dm", „Kategorie: automatisch“ / "Category: automatic", „Kategorie: automatisch, Kühlregal“ / "Category: automatic, Chilled". After a pick a chip looks normal again, with its store or category icon, and is named „Laden: <name>“ / "Store: <name>" or „Kategorie: <name>“ / "Category: <name>" (also when the pick equals the guess); a pick that differs from the guess turns it honey. At 358 px both chips and Schließen fit one line; long names or large text wrap the second chip under the first. The chips fold out their options inline: the store chip „Ohne Laden“ / "No store" first (left out while a store search is typed), then the stores in their order, then „Neuer Laden“ / "New store" (named „Neuen Laden anlegen“ / "Add a new store"); the category chip its categories. A pick applies to the next row taken, whichever it is, then resets. Rows tell their own store with a small badge when it differs from the chip. A pick that differs from the guess is remembered for that name (see the stores feature). With more than five stores the store fold starts with a search field „Läden durchsuchen“ / "Search stores"; Enter there picks the store of that name or starts a new one.
- `qa-added` (without `add-sheet-compact`: `VH_FLAGS_OFF=add-sheet-compact`; users get no note after a plain add, `qa-compact`) after an add the note reads „✓ Hinzugefügt: <name> → <store>“ / "✓ Added: <name> → <store>" (without „ → <store>“ when no store) with a „Rückgängig“ / "Undo" button, until the next keystroke. The note is no live region since job 474: the add is announced once, as „<Name> hinzugefügt“. Undo deletes the item again, and the cursor goes back to the field.
- `qa-duplicate` an item with the same name, brand and details already open on the same list is not added again (with several lists, „Butter“ can be open on two lists at once: driven 2026-11-09), also when two members (or a phone and Siri) add it at the same moment: the server keeps the first and the second phone shows that one (job 64, trigger `items_skip_duplicate`). Typed while it is on the list, the note reads „<name> steht schon auf der Liste“ / "<name> is already on the list", with no check mark and no undo (this note stays in the compact sheet users have).
- `qa-dedupe-hint` an item whose spelling variant or synonym is open (Karotten with Möhren open) is added anyway; once the server confirms it, the note gains a line „Möhren steht schon auf der Liste“ with „Zusammenführen“ / "Merge". Merging keeps the open item with merged quantities ("500 g" + "1 kg" = "1,5 kg") and shows „Zusammengeführt: 1,5 kg Möhren“ / "Merged: 1,5 kg Möhren" with „Rückgängig“ / "Undo", which brings both back. A merge keeps no price (job 246): the merged-in item comes back from „Rückgängig“ without its price, the kept item keeps its own; in the app the merge is undone only from that note or snackbar; the server keeps the merge record 30 days, then deletes it. With the sheet closed the same hint is a snackbar for 6 seconds.
- `qa-due` with the field empty the sheet lists the due items as „Wieder fällig“ rows, then items used in the last 30 days as „Zuletzt verwendet“ rows, 10 rows in all (see the usuals feature); with neither it says „Tippe, um Vorschläge zu sehen“ / "Type to see suggestions". While the field is empty (on opening, after an add) at most three rows show whole and the rest scroll (in the compact sheet users have, the sheet as tall as its rows; without it, under the note in a fixed room of three rows); the cap grows with large text so three rows stay whole (#198; driven 2026-11-04: 3 of 4 rows whole).
- `qa-offline` without a reachable server the rows are the ones `qa-device-catalog` makes at every key anyway: the typed line split into name, brand, details and quantity (multipacks too), „Schon mal gekauft“, other packs, kinds, sizes, brands and catalogue words, with the store the server would give. What follows in this bullet is the flag-off sheet (`VH_FLAGS_FULL=0`): the typed line (name and quantity only: no brand, details, store or category; the server adds them once the add syncs, `offline-details`), then up to 5 of the household's usuals („Schon mal gekauft“) cached on the device, matched as the server matches: same name, start, a word's start, inside (from 4 letters), typo (from 3 letters), so „Hafermlch“ and „milch“ find Hafermilch offline too (live: „Duschgl“ offers „Duschgl, Wie getippt“ and „Duschgel, Schon mal gekauft“). The empty field offline still shows the „Wieder fällig“ rows from the device. Offline the typed line is read like online, number words and halves included („zwei Gurken“ gives Gurken with 2; driven 2026-11-05 with `journeys/offline.mjs`); only a multipack („6 x 1,5 l Wasser“) and the brand and details split need the server, which splits brand and details when the add syncs (job 111).
- `qa-clear` a ✕ in the bar (tooltip „Eingabe leeren“ / "Clear") appears while the sheet is open and text is typed; it empties the field and keeps the sheet open.
- `qa-close` (users: `qa-compact-close`) „Schließen“ / "Close", Escape, or a tap on the dimmed list closes the sheet and clears the field and the chip picks; switching to another tab closes it too. Opening again starts blank. After a close, a tap on the field or typing opens the sheet again. Nothing else does: an Escape right after an add, a row taken with Enter or a tap, closes the sheet for good (job 76; on the web the field's refocus after the add used to reopen it).
- `qa-length` the field takes at most 120 characters.
- `qa-stable-rows` (flag `input-stable-rows`, on for users; with `on-device-catalog` also on, as users have it, the rows are `qa-device-catalog`'s and the typed row is split as the server splits it, so the unsplit typed row described below shows only with `VH_FLAGS_OFF=on-device-catalog`) the rows do not jump while typing. Every key shows rows made on the device for the text typed now, in the same frame: the typed line (so „Wie getippt“ always reads the field, never the text of a key or two before) and the household's matching usuals, each with a category guessed on the device (the household's own category for that name, else the dictionary's). The server's answer then keeps those rows in place and in order: it fills in their category and sets their store, and adds its other rows below, 8 rows in all. Its reading of the typed line replaces the typed row only when it reads the same name, brand, details and quantity; otherwise the row keeps the typed text and the brand and details are split off when the add syncs („Windeln Pampers Größe 3“ with dm in the household shows „Windeln Pampers Größe 3, Wie getippt, dm“ and is stored as Windeln, brand Pampers, details „Größe 3“; driven 2026-11-16 on c2183ca6), where the flag-off sheet shows `qa-details`' split row. While a finger is on a row (pressed, or scrolling the rows) no row changes until it lifts, and a tap adds that row as shown; a finger on the chips holds nothing. A line typed with the brand or details of an item already open („Weihenstephan Milch“ with Milch, Weihenstephan open) says it is on the list, as with the flag off. An add made on the device sorts into its category's section at once; the server still decides the category when the add syncs. A new grocery the household has no store for goes to the store the household uses most for that category (from the stores it remembered for its other items), unless the item has its own remembered store, was set to „Ohne Laden“, or its brand has a store, which still win (`sw-store-memory`). Only adds made in the app get this; Siri, Alexa and AI assistants do not. With the flag off (`VH_FLAGS_FULL=0`) rows come only with the server's answer. No visual change either way: the sheet looks the same.
- `qa-feedback-list` (flag `add-feedback-list`, on for users, but with `add-sheet-compact` also on, as users have it, the list behind the sheet is `qa-compact-behind` instead; what follows needs `VH_FLAGS_OFF=add-sheet-compact,hide-categories`) while the sheet is open the list behind it shows its open items in walk order without store or category headings, then a section „Gerade hinzugefügt“ / "Just added" with this opening's adds in the order added (also from a folded store); the list scrolls to its end so the last add stands right above the sheet. The list's top bar (the household and list switcher and „Anpassen“), the sync pill and the partner's new-adds capsule fade out over the 300 ms glide (job 288) and the rows take their room up to the status bar, which keeps its background; they fade back in as the sheet closes, at once with reduced motion. An undone add leaves the section. Closing the sheet glides the list back into its stores and categories in 300 ms, the adds moving to their places, at the scroll position from before the opening; with reduced motion it switches at once. The list behind the scrim takes no taps and is hidden from screen readers while the sheet is open, as before. The sheet keeps one height while open, from the first state on: rows, notes and details always take the room of three rows and scroll inside it, and its top holds only the grab handle and ✕ „Schließen“, no store or category chips.
- `qa-added-details` (flag `add-feedback-list` without `add-sheet-compact`: `VH_FLAGS_OFF=add-sheet-compact`; users get `qa-compact-chips`) after an add, until the next letter in the field, the rows' room shows the added item's details under the „✓ Hinzugefügt“ note: „Menge“ / "Quantity" with − and + (when the amount can step; one adjustable screen-reader node, as in `qa-compact-chips`), the store chip („Laden: <name>“ / "Store: <name>", „Laden: Ohne Laden“ when it has none) and the category chip („Kategorie: <name>“ / "Category: <name>"), „Marke“ / "Brand" and „Eigenschaften“ / "Details", in one line that scrolls sideways (job 288); a chip's options fold out below the whole line, which scrolls up into view. A stepper or chip pick is saved at once; typing is saved 500 ms after the last key, or at once when a letter is typed in the add field, another row is taken or the sheet closes. Enter in a details field saves and returns to the add field. Not shown when the item was already on the list. A store or category picked there (also „Ohne Laden“) is remembered for that name like an edit: the next add of the name lands there. „Rückgängig“ on the add deletes the item like any delete and keeps what its details taught: the next add of the name lands at the picked store and category, and a wrong lesson is fixed in the next add's details (Peter t1071u, job 322, which reverted job 315's take-back; `public.undo_add` is a plain delete for the store builds that still call it). Driven 2026-11-20 with job 315's old journey: „Quark“ picked to Wochenmarkt and Getränke, undone, typed again: „Quark, Wie getippt, Wochenmarkt“, stored at Wochenmarkt under Getränke.
- `qa-compact` (flag `add-sheet-compact` on top of `add-feedback-list`, job 322, AS1; full since 2026-11-22, so this is the sheet users have) the sheet has no ✕ and no title line: only a slim grab handle, named „Schließen“ / "Close" for screen readers. After an add there is no „✓ Hinzugefügt“ note and no „Rückgängig“: a mistaken add is removed by closing the sheet and deleting its row. Before typing the sheet shows what is due again (or „Tippe, um Vorschläge zu sehen“) without the fixed room for three rows; while typing it grows to at most three rows (the others scroll inside) and shrinks back after the add. Duplicates are as without the flag, above the chips: „<name> steht schon auf der Liste“ for an add of what is open, and the merge hint with „Zusammenführen“, then „Zusammengeführt: …“ with its own „Rückgängig“. Driven 2026-11-20 with `journeys/add-sheet-compact.mjs` (de and en): one „Schließen“ in the open sheet, no added note or „Rückgängig“ after „Kefir“, „Kefir steht schon auf der Liste“ with „Zusammenführen“ after a second Kefir with other details.
- `qa-compact-chips` (flag `add-sheet-compact`) after an add, until the next letter, one row of chips under the handle: −, Menge (as wide as its text, "1" as the hint) and +, for screen readers one adjustable node „Menge“ / "Quantity" whose value ("2"; empty reads 1) a swipe up or down steps (TalkBack: the volume keys), − and + no stops of their own, the field its own node for typing (job 474; iOS and Android: on the web − and + stay the buttons „Eins weniger“ / „Eins mehr“); the store chip („Laden: <name>“, „Laden: Ohne Laden“) and, only with `hide-categories` off, the category chip („Kategorie: <name>“), without icons or arrows; and the details chip, a notes icon named „Eigenschaften“ / "Details", which shows "<brand>, <details>" once either is set. The row wraps onto more lines rather than scroll, and each chip takes at most half the row, its name cut with „…“ (so long names at large text keep it to two lines); the steppers are 34 × 44 px, narrower than the 44 px target, so the row fits one line on a 390 px phone (DECISIONS job 322, 8): in English it is one line on a 390 px phone (60 px, 132 px with the add bar, the prototype's 131), in German „Laden: Ohne Laden“ with „Kühlregal“ moves the details chip to a second line (111 px, 183 px with the bar). One chip is open at a time, right under the row: the store and category options in ONE line that scrolls sideways, the item's own option in view, none wider than the line („…“ at large text), the store search field, „Neuer Laden“ (with its chain suggestions and question, store-apps `sa-suggest` and `sa-ask`; `open-store-app` full since 2026-11-25); the details chip opens one field for the details only (hint „z. B. Bio, 1 l“), focused; Enter there saves it and returns to the add field. The brand is not edited here (only in the edit sheet). A step or pick is saved at once, typing 500 ms after the last key. Every control and open picker stays above the keyboard up to 310 % text on a 390 × 844 phone and 200 % on 360 × 640, and the sheet does not scroll (widget test `add_sheet_compact_test.dart`, also with the store „Hofladen Sonnenhang“ and the category „Vorrat & Konserven“; on the web build at 200 % in a 390 × 508 window every control is on screen with each picker open; at 310 % on the web without a soft keyboard the add bar's hint line takes three lines and the chips scroll instead). - `qa-compact-behind` (flag `add-sheet-compact`) the list behind the open sheet is empty until the first add, then shows only the last two adds still on the list, the newest lowest, right above the sheet, without „Gerade hinzugefügt“, the top bar or the list's cards. - `qa-match-rows` (flag `add-match-rows` on top of `add-sheet-compact`, job 324, AM2; full since 2026-11-25) while typing, the items on the shown list that are the same thing as the text (the same canonical key: the same name, a plural, another spelling or a synonym, whatever brand and details either has; „Milch“ is not „Hafermilch“ or „Vollmilch“; a word that folds onto another word's key is read by its spelling, as on the server, so „Schäufele“ is not „Schaufel“ and „Beeren“ not „beer“, while „Tomaten“ is „Tomate“, job 473) show as marked rows at the top of the one suggestions list, then the `+` row, then the sheet's other suggestions (job 340; they no longer hide). ## How to get to it (user POV)

- Open the app signed in to a household; the „Liste“ / "List" tab is the home screen and the bar „Was brauchst du?“ / "What do you need?" is at its bottom.
- Type, or tap the bar, then press Enter or tap a row.
- Right after an add, tap the amount steppers, the store chip („Laden: …“) or the details chip („Eigenschaften“) in the row of chips to change them. There is no category to pick and no „Rückgängig“: a wrong add is ticked off or edited on the list.
- Close with a tap beside the sheet, a swipe down on it, Enter in the empty field, or Escape (the grab handle is named „Schließen“ / "Close").
- Tap the empty bar to see what is due again.
- On iOS and Android the bar also has a microphone (see the dictation feature).

## Gotchas

- `VH_FLAGS_FULL=0` builds the flag-off sheet (what the e2e specs see): there, while the server answers slowly, „Wie getippt“ can still show an older text („K“ while the field says „Kefir“), and a tap adds that text. `input-stable-rows.mjs --expect off` reproduces it on purpose (driven 2026-11-16 on c2183ca6).
- While a trip runs (flag `trip-mode`, off for users since 2026-11-22), the trip strip sits right above the add field and hides while the add sheet, a price panel or the keyboard is up (trip-mode `tm-strip`). Users have no „Einkaufssumme“ bar above the add bar: with `prices-and-trip-total` (also off for users since 2026-11-22) the totals come after the open items (list-declutter `ld-total`; the bar shows only with `VH_FLAGS_OFF=list-declutter`).
- The mouse wheel scrolls the list anywhere, the add band and the tab pill included (job 159: `ScrollThrough` hands their wheel events to the page under them). `reveal` still points above the band.
- Use `typeInto` for typing: synthetic key events drop umlauts. Click the field first so the sheet is open, then type (text inserted during the opening tap can land in the DOM input but not in the app).
- While the sheet is open the list under the dimmed layer is out of reach; a click there closes the sheet. Close the sheet (Escape) before acting on list rows. Escape takes focus away from the field.
- Prefer Escape over „Schließen“ in recipes that go on typing; the specs pin that after „Schließen“ the next tap and typing still reopen the sheet, including a key typed before the next frame (`add-sheet.spec.ts`).
- After a tap on a row, a chip or Undo the field regains focus after about 50 ms on web; wait ~150 ms before typing without a click.
- Rows show in the key's frame from the device; the server's answer follows about 120 ms after the last keystroke and can fill in a store or category in a row's name. Wait for the row you want by name before clicking, and match rows by name regex, not index: the order depends on the household's history and the catalogue.
- `getByText` on a snackbar finds only a short-lived screen-reader copy; use `actionSnackBar(page, '<text>')`. The dedupe hint is a group named „Möhren steht schon auf der Liste“ in the sheet's note, a snackbar after closing.
- The hint (and, without `add-sheet-compact`, the note's „Rückgängig“) appears only until the next keystroke or the next add.
- A chip pick is remembered for that item name (store or category memory); later adds of that name land there. `helpers/launch.sh --fresh` (or `scripts/fg teardown <run>`) removes the run's household with its memory; use a fresh run for repeatable recipes.
- On phones the cursor does not come up on open; only a tap shows the keyboard. The iPhone behaviour is covered by `e2e/tests/iphone.spec.ts` in WebKit as an iPhone, not by a normal Chromium run (tests: one tap opens the sheet with the field focused; one tap after a tapped suggestion brings the keyboard back).
- The microphone does not exist on web, see the dictation feature.
- Typo rows were driven on 2026-11-01: „Hafermlch“ offers „Hafermilch, Aus dem Katalog“. A word already open on the list is not offered again, so „Joghrt“ offers „Jogurt“ when Joghurt is on the list.
- A new row can land below the fold; scroll to it (`reveal`) before asserting. Users see no category headings, so check an add's category through the API (`categories(name)`), as `quick-add.mjs` does on a plain launch.
- The ✕ in the bar is a button named „Eingabe leeren“ (seen in the ARIA snapshot of a drive, 2026-11-01).
- The catalogue („Aus dem Katalog“ / "From the catalog") follows the app language (job 470, `CatalogIndex.languageFor`): German shows the German terms, English the words of `supabase/classifier/dictionary.en.tsv` ("Yogh" offers "Yogurt", "mil" offers "Milk", "Oat milk"; no German term), another language English. Rows are written as an English list writes them, capitalised once: "Peanut butter", "Organic peanut butter". The server's answer asks for the same language (`suggest_entries`'s `p_lang`). In English a catalogue phrase completes from its first words and takes their place ("toilet p" offers "Toilet paper", "chicken br" "Chicken breast", "2 toilet p" "Toilet paper" with 2); after other words a one-word catalogue word comes only after a descriptor ("bio mil"); a word the classifier knows gets no typo rows ("Milch" offers nothing, "oat milk" nothing). German keeps its rule: the last word typed is replaced. A German word typed in the English app files as German (one classifier for every language).
- Item writes are optimistic: the row shows before the server has it. Assert stored state through the API and poll.

# Siri (Shortcut and native Siri)

A user can put things on the Snacklist by voice with Siri on an iPhone. Two ways exist. The Shortcut: the user creates an access key („Zugriffsschlüssel“, „Lesen und schreiben“) in the app and builds a three-step shortcut in Apple's Shortcuts app named „Einkaufsliste“; then „Hey Siri, Einkaufsliste“ dictates a sentence, Snacklist splits it into items and Siri reads the result back. Native Siri: with the iPhone app (iOS 17 or newer) signed in to a household, Siri understands „Etwas auf Snacklist setzen“ / "Add to Snacklist" and „Snacklist, was steht drauf?“ / "What's on my Snacklist?" with no setup. Native Siri is built and in test builds, but its announcement is held (native-siri hold, waiting for Snacklist PM and a device test), so do not promote it. Native Siri acts in the user's default household, not the one shown in the app, and its item suggestions come from that household's list. The default is picked in the switcher sheet: „‹ Haushalte“, then the row „Siri, Alexa & KI nutzen:“ with its household and list steps (list-declutter `ld-voice`). The Shortcut's access token stays in the household it was made in, whatever the default. Both act in the member's default list there (their pick in that row, else the household's first list), and an add can name another list (`siri-named-list`). Nothing needs Premium today.

## Sub-features

- `siri-shortcut` the Shortcut recipe: access key „Siri“ (Mehr → Zugänge → „Schlüssel erstellen“, „Lesen und schreiben“; with the flag or switch `unified-keys` off „Zugriffsschlüssel erstellen“), then the shortcut „Einkaufsliste“ (dictate text in German, POST to the voice address with `Authorization: Bearer fgp_…`, speak the result). German only for splitting.
- `siri-reply-added` spoken reply German: „Hinzugefügt: Milch, 2 Gurken, Klopapier.“
- `siri-amounts` an amount said before or after the item is its quantity: „zwei Gurken“, „Eier zehn Stück“, „Möhren zwei“ (reply „Hinzugefügt: 2 Möhren.“). A bare count after the item, as a word or digits, is always the quantity („Eier dreißig“ → 30 Eier, „Büroklammern hundert“ → „Hinzugefügt: 100 Büroklammern.“); only after a size word (Größe, Gr., Typ, Nr., Stufe, Klasse) it stays in the name (job 89; typed text keeps the stricter rule of `supabase/tests/quantity_parse.tsv`). Up front, a name that starts with a number word keeps it, as typed: „Drei Glocken Nudeln“ is one item, „drei Äpfel“ 3 Äpfel (job 159, the `name` rows of `supabase/tests/number_words.tsv`).
- `siri-reply-existing` already on the list: „Schon auf der Liste: Milch.“ (nothing added for it). Mixed: „Hinzugefügt: Brot. Schon auf der Liste: Milch.“
- `siri-reply-similar` a spelling variant or synonym is open: item is added and Siri names the open one in the „Schon auf der Liste:“ sentence, after the exact ones, each name once (job 68): „Hinzugefügt: Karotten. Schon auf der Liste: Milch, Möhren.“ Per added item at most three similar open ones are named, the oldest. A plain name whose item is open with a brand or the note Bio (and no other details), also in singular or plural, is held (job 112, Peter Q79): with „Butter“ (brand Weihenstephan) open, native Siri asks „Butter Weihenstephan steht schon drauf. Soll ich Butter trotzdem dazuschreiben?“ (EN "Butter Weihenstephan is already on the list. Should I add butter anyway?"; listed in `site/COPY_NEEDED.md`); yes adds a second, plain Butter („Hinzugefügt: Butter.“), no or no answer adds nothing („Schon auf der Liste: Butter Weihenstephan.“). The Shortcut cannot ask: it answers „Schon auf der Liste: Butter Weihenstephan.“ and adds nothing (driven over HTTP 2026-11-06; on demo-familie tick the seeded plain Butter first, or the reply is „Schon auf der Liste: Butter.“). Only the App Shortcut phrases ask; an item phrase handled by SiriKit lists answers like the Shortcut. Server side: the request carries `"ask": true`, the reply `outcome` `confirm` with `question` and `again`; the yes is `again` with `"confirmed": true`. Other details are another product and always add, naming the open one in full: „Butter“ with „Butter gesalzen“ open (stored as Butter, details gesalzen) answers „Hinzugefügt: Butter. Schon auf der Liste: Butter gesalzen.“; the same for passiert, laktosefrei, flavours. The open item is never changed; „Butter Kerrygold“ is another brand and is added. To get a second plain item while a branded one is open, the Shortcut and SiriKit lists cannot ask: say the full name („Butter ungesalzen“) or add it in the app.
- `siri-named-list` (job 207) a list named at the end of the sentence or in the request's `list` (Shortcuts parameter, SiriKit target list): „Luftballons zur Geburtstag Liste“ → Luftballons on Geburtstag, „Hinzugefügt zur Liste Geburtstag: Luftballons.“; unknown or ambiguous name → the default list and „Eine Liste „Party“ habe ich nicht gefunden. …“; with several lists every add names the list used, the seeded default list as „Einkaufsliste“ („Hinzugefügt zur Einkaufsliste: 2 Gurken, Klopapier.“, „Schon auf der Einkaufsliste: 2 Gurken.“, driven 2026-11-23 on d023441d), with one list the replies are unchanged.
- `siri-errors` the exact sentences, German and English (see below).
- `siri-limits` at most thirty items per sentence: „Mehr als dreißig auf einmal gehen nicht; sag den Rest bitte noch einmal.“ (EN "More than thirty at once doesn't work; please say the rest again."); text over 1000 characters is refused (too_long).
- `siri-native-add` native Siri adds in German or English; English reply „Added milk, eggs and bread to Snacklist.“
- `siri-native-open` „Zeig meine Snacklist“ / "Show my Snacklist" opens the app on the list from any screen (job 97).
- `siri-native-read` native Siri reads the open list: „Auf der Snacklist stehen 3 Sachen: …“ / „Die Snacklist ist leer.“ (EN "There are 3 things on your Snacklist: …" / "Your Snacklist is empty."); at most ten are named, then „und N weitere“ / "and N more" (exactly one more: „und eine weitere“ / "and 1 more").
- `siri-credential` the iPhone app creates its own Siri key „Siri (dieses iPhone)“ after sign-in in a household (other phones: „Siri (anderes iPhone)“); it ends with sign-out, leaving the user's last household, account deletion or revoking it (leaving one of several households moves it to the user's next household, so Siri keeps working; from code, `households_multi.sql` `leave_household`); at most five Siri keys per account (the oldest ends). Works only for Siri; the MCP server refuses it.
- `siri-permission` (job 467) the iPhone app asks iOS's question whether Snacklist may use Siri (Settings › Apps › Snacklist › Siri › „Mit Siri verwenden“ / "Use with Siri") whenever it comes forward and the user has not answered yet, signed in or not, and again when it stores a new Siri key. Unanswered, SiriKit gives Snacklist no Lists request; on TestFlight 1541 English Siri answered "Snacklist hasn't added support for that with Siri" and asked to turn on Snacklist's shortcuts. iOS shows the question once. unverified on a device (no iPhone here; `SiriAuthorizationTests` in RunnerTests, Peter's retest in docs/NEEDS_PETER.md „Job 467“).
- `siri-card` Zugänge on iPhone shows the card: „Sag zum Beispiel: „Hey Siri, etwas auf Snacklist setzen“.“ (EN "For example, say “Hey Siri, add to Snacklist”."; job 80 removed „funktioniert jetzt ohne Einrichtung“, which suggested earlier users had to set it up) with the link „Siri-Sätze anzeigen“ (dialog „Siri-Sätze“, „Auf Deutsch“ / „Auf Englisch“, the four phrases each: „Etwas auf Snacklist setzen“, „Snacklist, füge etwas hinzu“, „Füge <Eintrag> zu Snacklist hinzu“, „Snacklist, was steht drauf?“). If the user has an old key named like the Shortcut (Siri, Kurzbefehl, Shortcut): „Den alten Kurzbefehl brauchst du nicht mehr. Seinen Zugriffsschlüssel „<Name>“ kannst du unten löschen.“ (EN "You no longer need the old shortcut. You can delete its access key “<name>” below.") Revoking a Siri key asks „Siri-Zugang widerrufen?“ / „Siri kann auf dem iPhone dann nichts mehr hinzufügen. Beim nächsten Start von Snacklist dort wird Siri neu eingerichtet.“
- `siri-suggestions` the app tells Siri which item names to offer for „Füge <Eintrag> zur Snacklist hinzu“ / "Add <item> to Snacklist": the household's usuals first, then open items, then recently bought, each item once, at most 50, sent at most every 2 seconds after the list changes. Each carries up to two synonyms: the household's other names for the same item (same canonical key, „Möhren“ for „Karotten“), so „Füge Möhren zu Snacklist hinzu“ adds the household's „Karotten“ (job 97). Names only, nothing else; at most 100 names and synonyms in all.
- `siri-dictation` related, not Siri: the microphone button in the add bar on the iOS and Android apps (tooltip „Diktieren“, while listening „Diktat beenden“, hint „Ich höre zu …“). Not on web.

## How to get to it (user POV)

- Shortcut: Mehr → Zugänge → „Zugriffsschlüssel“ → „Schlüssel erstellen“, pick „Lesen und schreiben“ (the default „Nur lesen“ makes every add fail, below; with unified keys off, an older screen: „Zugriffsschlüssel“ → „Zugriffsschlüssel erstellen“), name `Siri`, copy the key once; then Shortcuts app → new shortcut „Einkaufsliste“ with actions „Text diktieren“ (Deutsch, nach Pause, prompt „Was soll auf die Liste?“), „Inhalte von URL abrufen“ (POST, `https://jdwqrallbpdbshrdhenk.supabase.co/functions/v1/voice?format=text`, header `Authorization: Bearer fgp_…`, JSON field `text` = Diktierter Text), „Text sprechen“ (Inhalte der URL). Say „Hey Siri, Einkaufsliste“. If Siri opens Reminders instead, rename the shortcut, for example „Einkauf notieren“. Public guides: DE „Snacklist per Siri: Kurzbefehl einrichten“, EN "Snacklist with Siri (German only for now)" on snacklist.app (their native-Siri section is tagged `since=1.0.0 once=native-siri`: hidden in production until that release and until the `native-siri` hold is released).
- Native (iPhone, iOS 17+, signed in, in a household): „Hey Siri, etwas auf Snacklist setzen“ then the items; English „Hey Siri, add something to my Snacklist“. Phrases (Zugänge → „Siri-Sätze anzeigen“): EN "Add to Snacklist", "Add something to my Snacklist", "Add <item> to Snacklist", "What's on my Snacklist?"; DE „Etwas auf Snacklist setzen“, „Snacklist, füge etwas hinzu“, „Füge <Eintrag> zu Snacklist hinzu“, „Snacklist, was steht drauf?“. All phrases are in `app/ios/Runner/AppShortcuts.xcstrings`, a set per language for each Swift phrase (job 97: 30 German and 24 English, the Show phrases „Zeig meine Snacklist“ / "Show my Snacklist", which open the app on the list, included); the phrase without an item comes first, so Siri asks for the items, and no German phrase says „Liste“ (so no „Einkaufsliste“) or is a bare „Auf meine Snacklist“ (Reminders' grammar; jobs 92 and 97). Siri also takes the app name as Siri may write it (German „Snack List“, „Snäcklist“, „Snecklist“, hint „snäcklist“; English "Snack List", "Snack-list", "Snack Lists", hint "snack list"; job 174, after Hummlist's Humlist/Hamlist/Homlist; none ends in „Liste“, job 97), says it as „Snacklist“ (CFBundleSpokenName), and the voice parser drops these and Hummlist's old spellings from items. Negative phrases („Füge etwas zur Einkaufsliste hinzu“, "Add something to my shopping list") keep the system's own list requests away from Snacklist. An item phrase matches only the 50 names the app suggested; any other item („Füge Zahnpasta zu Snacklist hinzu“) reaches the app through SiriKit's Lists domain (INAddTasksIntent, reading INSearchForNotebookItemsIntent), which the app handles in-app and sends to `voice` the same way. That needs „Mit Siri verwenden“ for Snacklist: since #747 the app asks iOS's Siri question each time it comes to the front until the user answers (`AppDelegate.swift`, job 467). Siri listens in the iPhone's language, not the app's.
- Device test (Peter's iPhone; docs/SIRI_SHORTCUT.md, „Gerätetest (job 97)“): Siri language Deutsch (Deutschland), then English; Einstellungen › Siri › Antworten › „Transkription immer anzeigen“ on; Kurzbefehle app shows the Snacklist tile with „Zu Snacklist hinzufügen“, „Meine Snacklist vorlesen“ and „Snacklist öffnen“; voice first, then Type to Siri, each phrase of the table; record build number, the transcript Siri shows and the outcome per phrase. Signed out, Siri answers in its sheet and the app stays closed.
- Failure sentences German / English (exact): 
  - key missing or wrong: „Der Zugriffstoken fehlt oder ist ungültig. Erstelle in der Snacklist-App unter Mehr, Zugänge einen neuen.“ / "I couldn't sign in to Snacklist, so nothing was added. Open Snacklist and sign in again."
  - a read-only key adding (users' Zugänge since 2026-11-23, ai-assistants `ai-unified-keys`; 403 `read_only`): „Dieser Zugriffsschlüssel darf nur lesen, also wurde nichts hinzugefügt. Erstelle in der Snacklist-App unter Mehr, Zugänge einen zum Lesen und Schreiben.“ / "This access key can only read, so nothing was added. Create one that can read and write in the Snacklist app under More, Access." Reading aloud still works with it.
  - no household: „Du bist noch in keinem Haushalt. Leg in der Snacklist-App einen an oder tritt einem bei.“ / "You're not in a household yet, so nothing was added. Create one or join one in the Snacklist app."
  - no text: „Ich habe keinen Text bekommen. Sag zum Beispiel: Milch, zwei Gurken und Klopapier.“ / "I didn't get any text, so nothing was added. Say for example: milk, two cucumbers and toilet paper."
  - nothing understood: „Ich habe nichts verstanden, was auf die Liste soll. Sag zum Beispiel: Milch, zwei Gurken und Klopapier.“ / "I didn't understand anything to put on the list. Say for example: milk, two cucumbers and toilet paper."
  - too long: „Das war zu lang. Sag höchstens dreißig Dinge auf einmal.“ / "That was too long, so nothing was added. Say at most thirty things at once."
  - server: „Das hat leider nicht geklappt. Versuch es gleich noch einmal.“ / "Sorry, that didn't work, nothing was added. Please try again in a moment."
  - not POST: „Bitte schick den Text per POST.“ / "Please send the text with POST."
- Other replies: EN existing "Already on the list: milk." ; EN similar "Added Karotten to Snacklist. Already on the list: Milch and Möhren."; parse-only (the app's microphone, German) „Verstanden: Milch, Brot.“ / EN "Got it: milk and bread."
- Items appear on all phones within seconds.

## Driving it with Playwright

Preconditions:

- Web cannot run Siri. Only the server side is drivable, over HTTP against the LOCAL stack, as `e2e/tests/voice.spec.ts` does. Seeded household „Familie Brandt“, signed in. Never call production.
- Helpers in `e2e/tests/voice.spec.ts`: `say(token, text, '?format=text')`, `ask(token, { text, mode, lang })`, `sessionToken(email)`; a key from `(await apiAs(email)).rpc('create_personal_access_token', { p_name: 'Siri' })` (works because a password session carries a `session_id`; since #638 nothing else may make one) or, for native Siri, `rpc('create_siri_credential')`. `functionsUrl` + `/voice`. Run: `scripts/verify.sh --only e2e -- tests/voice.spec.ts`.

- **Create the key in the UI.** `openMore(page, 'Zugänge')`, `getByRole('button', { name: 'Schlüssel erstellen' })` (`'Zugriffsschlüssel erstellen'` with the switch `unified_keys` off), `typeInto(getByRole('textbox', { name: 'Name' }), 'Siri')`, `getByRole('radio', { name: /^Lesen und schreiben/ }).click()`, `getByRole('button', { name: 'Erstellen', exact: true })`, read `getByText(/^fgp_/)`, `getByRole('button', { name: 'Fertig' })`.
- **Dictate.** `say(token, 'Zwei Gurken und Klopapier')` returns status 200 and JSON `speech` „Hinzugefügt: 2 Gurken, Klopapier.“; `say(token, 'Milch und Brot', '?format=text')` returns the body only. In the app: `openTab(page, 'Liste')`; `itemRow(page, 'Klopapier')` visible without reload.
- **Duplicate and similar.** Say „Milch“ twice: second answer „Schon auf der Liste: Milch.“. Say „Möhren“ then „Karotten“: both on the list, speech „Hinzugefügt: Karotten. Schon auf der Liste: Möhren.“
- **Errors.** `say('fgp_not-a-token', 'Milch', '?format=text')` is 401 with the unauthorized sentence; text „Bitte, danke“ is 422 with „Ich habe nichts verstanden …“.
- **Native, English.** `ask(token, { text: 'milk, eggs and bread', mode: 'add', lang: 'en' })`: `outcome` `added`, `speech` "Added milk, eggs and bread to Snacklist."; again with `milk`: `nothing_added`, "Already on the list: milk."; `ask(token, { mode: 'read', lang: 'en' })`: `total` 3 on a fresh household as in `voice.spec.ts` (on demo-familie the 15 baseline items count too: driven 2026-11-14, „Auf der Snacklist stehen 17 Sachen: …“ after two adds), speech starts "There are 3 things on your Snacklist: "; German `lang: 'de'`: „Auf der Snacklist stehen 3 Sachen: “. A request without `lang` answers exactly as the Shortcut always did and has no `outcome`.
- **Ending.** Revoke in the app (`getByRole('button', { name: 'Siri widerrufen' })`, then `getByRole('button', { name: 'Widerrufen' })`): the next request is 401. For the Siri credential: signing out the session that created it also gives 401, `outcome` `unauthorized`; the MCP endpoint answers 401 to it.

## Gotchas

- Siri stays free under the integration lock: on a plain `helpers/launch.sh` stack (`integration_lock` on, as in production) a key made in Zugänge by a member without Premium adds through `/voice` („Hinzugefügt: 2 Gurken, Klopapier.“) while the same key on MCP gets „Dafür brauchst du einen anderen Snacklist-Tarif …“ (driven 2026-11-26 on 2694ab4a). `scripts/verify.sh --only e2e -- tests/voice.spec.ts` on such a stack fails „Siri and MCP agree on what is already on the list“ and „a different size or type is a new item“: their MCP half is refused by the lock, not Siri. Turn the switch off for that run (`update public.app_switches set enabled = false where key = 'integration_lock'`, then back on) or run it on a stack the skill did not launch. alexa.spec.ts and alexa-en.spec.ts pass with it on.

- Siri with Apple Intelligence (App Intents actions such as ticking items off by voice) is decided but not built (`docs/PRODUCT_FEATURE_MAP.md`, `siri-ai-app-actions`). No Siri path ticks items.

- German device (job 71: build 1097 only opened the app for every German phrase): the checks are `docs/NEEDS_LEAD.md` "Job 71". Turn on Always Show Speech to see the words Siri heard for the app name, and type the phrase with Type to Siri to test the phrase without speech recognition. Without a device, `deno run --allow-read scripts/siri-phrases.ts` (lint gate) proves the tables, `scripts/siri-target.py` (lint gate) that the release app's Runner target builds the Siri code and phrases, `scripts/app-shortcuts-bundle.py` (ios gate) that the built app carries the App Shortcuts, and the ios gate's log shows the German training (`Training '…' for de`, `Application name … for de`).
- SiriKit Lists failures (signed out, no household, any error) answer `failure` since job 97: Siri says its own sentence and the app stays closed. Only „Zeig meine Snacklist“ / "Show my Snacklist" opens the app.
- Server side of the German spellings: `ask(token, { text: 'Füge Milch zur Snackliste hinzu', mode: 'add', lang: 'de' })` adds „Milch“, not „Milch zur Snackliste“.
- Native Siri and the „Siri“ card on Zugänge exist only in the iOS app (a method channel to the iPhone). On web and Android Zugänge shows no Siri header and card (a Siri key made on an iPhone still shows as „Siri (anderes iPhone)“ there). There is no way to drive Siri voice or the Shortcuts app on this harness. unverified (needs a real iPhone; Peter's device test is pending, per the native-siri hold).
- The native-siri hold: the code is on main and ships in iOS test builds, but the changelog and site announcement wait for Snacklist PM. Describe native Siri only as "coming", never as released.
- The Shortcut path is live today, but it is manual and splits German only (the English splitter is used only when the request names `lang: 'en'`, which the Shortcut does not send).
- Integration lock: Siri stays free (job 184). Even with the server switch on, the voice function adds and reads for a household without Premium and never answers `premium_required` (driven 2026-11-13 on the local stack: switch on, „Zwei Gurken und Klopapier“ answered 200 while MCP refused). The iOS app keeps its old sentence „Sprachbefehle sind Teil von Snacklist Premium. …“ only for older servers; nobody hears it. OAuth tokens (MCP and AI-assistant clients, also the Alexa link's token) get 401 `unauthorized` from the voice function since job 213, so a locked client can't add through it; the app's session, the Siri credential and personal access tokens still work (`e2e/tests/integration-lock.spec.ts`, `voice/handler_test.ts`).
- Voice replies must be quoted exactly from the lists above; Siri reads them aloud verbatim.
- The `list` field and `mode` / `lang` request fields are the contract for the native app; keep them out of copy.
- The in-app microphone is mobile-only; Playwright on web cannot drive it.

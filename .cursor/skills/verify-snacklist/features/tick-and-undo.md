# Ticking items, "Zuletzt verwendet" and undo

A tap on an item's row ticks it off: a line draws across the item's words, the row turns mint, then it closes and the rows below move up (about 0.4 s). A store divider whose last item leaves closes with it (users see no category dividers: `hide-categories`); when that store is matched to a chain with an app, the ticker gets the card „<Store> ist erledigt“ with „App öffnen“ at the top of the list (store-apps `sa-done-card`, `open-store-app` full since 2026-11-25). No snackbar appears, so a tick has no „Rückgängig“; screen readers hear „<Name> abgehakt“ / "<Name> ticked off". With the flag `trip-mode` (off for everyone since 2026-11-22, Peter HP2, job 401; users' ticks ask nothing) and while no shopping trip runs, an own tick then opens the sheet „Kaufst du gerade ein?“ / "Are you shopping right now?" (`tu-shop-ask`), whose „Zurücknehmen“ takes the tick back; after „Nein, nur abgehakt“ the sheet stays away for an hour. Ticked items collect in a section at the bottom of the list, „Zuletzt verwendet“ (the 20 newest, each thing once, none that is on the list again), which starts open; a tap on its header folds it, and the device remembers the fold (`tu-used-open`). A tap on an item there puts it back on the list, in the place it had, without a snackbar. Ticking is how an item leaves the list; the edit sheet has no delete since job 149. Other actions with an undo: a screen reader's delete on a row and a merge of duplicates. An add has none in the compact sheet users have (the „Hinzugefügt“ note with „Rückgängig“ needs `VH_FLAGS_OFF=add-sheet-compact`).

## Sub-features

- `tu-tick` a tap on a row ticks it: strike-through across quantity and name (180 ms), the row tints mint, then fades and closes (260 ms); the tick commits 440 ms after the tap and is saved on the server (survives a reload). The device has the tick from the tap on: it is saved there with the list's queue at once, and a start that finds it shows the item ticked and sends it (job 222 review 1). When the row or the app goes away before the 440 ms are over, the tick commits then (job 222): the app goes to the background, the page reloads or its tab closes, the row's store is folded, the row scrolls out of the lazily built list, or the list is left for another household; a row that draws no frames (its tab in the background) commits after 880 ms. No snackbar. Driven 2026-11-16 on c2183ca6: Butter tapped, the page closed 60 ms later, the device cache already held the tick, and a new page found Butter `bought` on the server and off the list. With reduced motion the struck row shows at once, holds 260 ms and goes without the close.
- `tu-shop-ask` (flag `trip-mode`, off for users since 2026-11-22; `VH_DEFINES="FLAGS_ON=trip-mode"` for a drive) after the row has left, while no trip runs, an own tick opens the sheet „Kaufst du gerade ein?“ / "Are you shopping right now?" with „Ja, Einkauf starten“, „Nein, nur abgehakt“ / "No, just tick it off" and, under „Aus Versehen abgehakt?“, „Zurücknehmen“, which puts the item back on the list (status `active`, in its old place). „Nein, nur abgehakt“ or closing the sheet keeps the tick and snoozes the question for 60 minutes (job 357): ticks in that time ask nothing. The snooze is kept per member on the device (it survives a reload, and a sign-out forgets it); „Zurücknehmen“ snoozes nothing. A tick of an item in a pharmacy store asks nothing; while a trip runs nothing is asked (trip-mode `tm-ask`, `tm-pharmacy`). It also comes offline. Driven 2026-11-19 on af0287cf (DE, EN); the snooze driven 2026-11-22 on 746d8d09 (DE, EN).
- `tu-tick-a11y` each row is a checkbox (unchecked while open, checked while it leaves) and the tick is announced „<Name> abgehakt“ / "<Name> ticked off". There is no visible check box.
- `tu-used-section` „Zuletzt verwendet“ / "Recently used" is a section below the list (open at first for users, `tu-used-open`); it exists only while at least one item is ticked. With several lists it holds the ticks of the shown list (the one picked in the switcher). A tick also ends every „Ich bringe das“ on that item (lists-and-claims). It holds up to 20 ticked items, newest tick first, one row per thing (the same item or another spelling of it, its newest tick), and none for a thing that is on the list again; each drawn like the list's row (icon, quantity in bold before the name, then brand · details) but faded. It is built from the household's 50 newest ticked rows across all its lists, then filtered to the shown list, so fewer than 20 rows show when many of them are the same thing or were ticked on another list.
- `tu-used-open` (job 367, flag `recently-used-open`, full since 2026-11-22, so users have it): „Zuletzt verwendet“ starts open, rows faded as before, no count in the header, nothing added to the add field. A fold by hand (tap the header) is remembered on the device (`ListPrefs.folded`, key `recently-used`) and the section then starts closed. Flag off (`VH_FLAGS_OFF=recently-used-open`): starts closed every time. Tests: `app/test/list/recently_used_open_test.dart` (open by default, no title extras, flag arriving late, fold across a restart). Driven 2026-11-23 on d023441d with `journeys/tick-and-undo.mjs`: the ticked Butter showed under the open section without a tap, a tap on the header folded it.
- `tu-put-back` a tap on a row under „Zuletzt verwendet“ puts it back on the list in its old store, category and position. No snackbar.
- `tu-delete-undo` the row's screen-reader action „Löschen“ / "Delete" (VoiceOver, TalkBack; the edit sheet's button is gone since job 149) removes the item and shows the snackbar „<Name> gelöscht“ / "<Name> deleted" with the action „Rückgängig“ / "Undo", which brings the item back (the server row is re-created). When the same item is open on the list again by then (a partner added it), Undo shows that item as it is and adds no second one (job 64b, `put_item`). Not drivable on web: Flutter web does not expose custom semantics actions.
- `tu-added-undo` (only without `add-sheet-compact`: `VH_FLAGS_OFF=add-sheet-compact`; users' adds have no undo, quick-add `qa-compact`) after an add, the add sheet shows „✓ Hinzugefügt: <Name>“ (or „✓ Hinzugefügt: <Name> → <Store>“) with „Rückgängig“ until the next keystroke; Undo removes the item again (what it means for a store or category picked on that add: quick-add `qa-added-details`, classifier).
- `tu-merge-undo` an add of exactly an open item (same name, brand and details) is not added: the note says „<Name> steht schon auf der Liste“ / "<Name> is already on the list" without a button. When the add is another spelling of an open item, it goes through and the note offers „Zusammenführen“ / "Merge"; afterwards „Zusammengeführt: <item>“ with „Rückgängig“ undoes the merge. Outside the add sheet the same offer is a snackbar „<Name> steht schon auf der Liste“ with „Zusammenführen“ (6 s).
- `tu-no-swipe-delete` a swipe across a row does nothing: it neither deletes, ticks nor edits (job 78; a hold edits).

## How to get to it (user POV)

- Tick: tap an item row on the list tab. (With trip-mode on, not for users today: answer „Kaufst du gerade ein?“; „Nein, nur abgehakt“ keeps the tick, „Zurücknehmen“ takes it back.)
- Put back: scroll to the bottom of the list, tap the item under „Zuletzt verwendet“ / "Recently used" (if it was folded, tap the header to open it first).
- Screen reader users: a row also offers the actions „Bearbeiten“ and „Löschen“ (delete without the sheet, same snackbar with „Rückgängig“).

## Driving it with Playwright

Preconditions:

- Seeded household „Familie Brandt“, signed in on the list, analytics declined, onboarded; the demo items include Butter, Nudeln and Reis without a quantity and „6× Bananen“ with one.
- Browser locale de-DE, viewport 480x900 or 390x844.

- **Scripted.** `helpers/drive.sh tick-and-undo` (`journeys/tick-and-undo.mjs`; `--item <name>`, default Butter; `--second <name>`, default Reis / Rice; `--lang en`) first ticks the second item and takes it back with „Zurücknehmen“ (stored `active`), then ticks the item, answers „Nein, nur abgehakt“, checks there is no „Rückgängig“ and the stored `bought`, proves „Zuletzt verwendet“ started open and folds on a tap (with `recently-used-open`, as users have it), puts the item back, and ticks the second item again: no question within the hour after the no (it goes back on the list through the API). PASS or FAIL. Without `VH_DEFINES="FLAGS_ON=trip-mode"` (a plain launch since 2026-11-22) no question comes: it skips the take-back, the no and the snooze and checks the tick and the put-back only. `--lang en` needs the English household (`launch.sh --scenario demo-family-en --fresh`), which has Rice. Passed 2026-11-22 on 746d8d09 in DE and EN (trip-mode build); on a plain launch 2026-11-23 on d023441d (DE). A run that fails after the tick leaves the item ticked: put it back (`scripts/fg db query --write`) or `launch.sh --fresh` before the next run. The steps below use `tick`, `putBack`, `usedRow` and `actionSnackBar` from `e2e/tests/helpers.ts`; `helpers/lib.mjs` has `itemRow`, `reveal` and `answerShopAsk(page, L, key)` (clicks the sheet's button by ARB key, default `shopAskNo`; `shopAskTakeBack` for „Zurücknehmen“), but not `tick`, `putBack`, `usedRow` or `actionSnackBar`.
- **Tick.** Tap the row. `tick(page, 'Butter')` (reveals the row, clicks `itemRow(page, 'Butter')`). Observable result: `itemRow(page, 'Butter')` count drops by 1; `page.getByRole('button', { name: 'Rückgängig' })` count is 0 and no snackbar group named „Butter abgehakt“ (`actionSnackBar(page, 'Butter abgehakt')` count 0; the same words exist only as the screen-reader announcement). On a plain launch no sheet follows. With `FLAGS_ON=trip-mode`: `page.getByText('Kaufst du gerade ein?', { exact: true })` is visible; `answerShopAsk(page, L)` clicks „Nein, nur abgehakt“ and waits for the sheet to go.
- **Take back from the question** (`FLAGS_ON=trip-mode`). Before any „Nein, nur abgehakt“ in this browser context (a no snoozes the question for an hour; a new context starts without it): tick Reis, then `answerShopAsk(page, L, 'shopAskTakeBack')`. Observable result: `itemRow(page, 'Reis')` visible again, its `status` `active` in the API.
- **Snooze** (`FLAGS_ON=trip-mode`). After „Nein, nur abgehakt“, tick another item: `answerShopAsk(page, L)` returns false (no sheet in 3 s). The device keeps it in localStorage under `trip.snooze.<user id>`; removing that key and reloading brings the question back.
- **The used section.** It starts open on the users' build: `reveal` the header `page.getByRole('button', { name: 'Zuletzt verwendet', exact: true })` and `usedRow(page, 'Butter')` is there without a click. A click on the header folds it (`usedRow` count 0, also after a reload); a second click opens it. With `VH_FLAGS_OFF=recently-used-open` it starts folded and the first click opens it. Observable result: `usedRow(page, 'Butter')` visible; its accessible name is the item name, then details/quantity, then „Wieder auf die Liste“, for example `Butter Wieder auf die Liste`, or `Bananen 6 Wieder auf die Liste` after ticking „6× Bananen“.
- **Put back.** `putBack(page, 'Butter')` (or `usedRow(page, 'Butter').click()`). Observable result: `itemRow(page, 'Butter')` visible again, `usedRow(page, 'Butter')` count 0, no snackbar (`page.getByRole('button', { name: 'Rückgängig' })` count 0; the old text no longer exists). In a store section the row returns to its old position (`list-walk-order.spec.ts` checks the row order).
- **Persistence.** After tick or put back, `page.reload()` then `expect(addField(page)).toBeFocused()`; the row is gone/back. A second view: the `items` row's `status` is `bought` / `active` through the API as the user.
- **Delete and undo.** Not in the web UI since job 149 (see `tu-delete-undo`); a delete through the API (`deleteItem(api, page, item)` in `e2e/tests/catalog.ts`) shows no snackbar.
- **Hidden while on the list.** Tick Reis, add „Reis“ again in the add bar: `usedRow(page, 'Reis')` count goes from 1 to 0.
- **Add undo** (`VH_FLAGS_OFF=add-sheet-compact`; users' adds have none). Type an item that is not on the list with `typeInto(addField(page), 'Joghurt')` and press Enter; the note „✓ Hinzugefügt: Joghurt“ shows with button „Rückgängig“; click it and `itemRow(page, 'Joghurt')` is gone. (A seeded name such as Butter is already on the list: its note has no „Rückgängig“.)
- **Spec coverage.** `e2e/tests/list.spec.ts` (tick without snackbar, put back, reload persistence, duplicate add), `e2e/tests/list-walk-order.spec.ts` ("a tap ticks, a tap under Zuletzt verwendet puts it back in place"), `e2e/tests/already-on-list.spec.ts` (an offline tick replayed onto the partner's item), `e2e/tests/tick-leave.spec.ts` (a reload or a closed tab right after the click keeps the tick, also a tab that closes while the page is busy; Chromium, WebKit and Firefox), `e2e/tests/dedupe.spec.ts` („Zusammenführen“ and its „Rückgängig“). Scripted: `helpers/drive.sh tick-and-undo [--lang en] [--item Butter]`. Run `scripts/verify.sh --only e2e -- tests/list.spec.ts`.

## Gotchas

- With `FLAGS_ON=trip-mode`, the question „Kaufst du gerade ein?“ (`tu-shop-ask`) has a barrier over the list: answer it before the next click on the list, or the click lands on the barrier. „Ja, Einkauf starten“ starts a trip (trip-mode); later ticks then ask nothing until it ends.
- A plain launch asks no question after a tick (trip-mode off for users since 2026-11-22). `VH_FLAGS_FULL=0` builds the flag-off list (what the e2e specs see): no question after a tick, list tabs instead of the switcher. There are no list tabs on the users' build: the shown list is picked in the switcher (list-declutter).
- The add field floats over the list's bottom edge: a tap in its band, gutters included, opens the field and never ticks the row under it. `reveal` the row clear of the field first.
- A used row's gestures are off except the tap: no tick, right click or hold. Its accessible name ends in „Wieder auf die Liste“; `itemRow` excludes names ending that way, `usedRow` requires it.
- „Zuletzt verwendet“ starts open for users, so a click on its header folds it: do not click it before looking for a row (an old recipe that clicked to unfold now hides the row). The fold is kept per device; a new `openApp` context starts open. The list is long: scroll to it (`reveal`) first.
- The add sheet's rows for an empty field are also named „<Name>, Zuletzt verwendet“; while the sheet is open a `getByRole('button', { name: 'Zuletzt verwendet' })` without `exact: true` can match them (`putBack` in `e2e/tests/helpers.ts` does not pass `exact`).
- In English the used row's name ends in "Back on the list", not a translation of the German; `usedRow`'s pattern is German only.
- `getByText` finds the screen-reader copy of a snackbar only briefly; use `actionSnackBar` for snackbars with an action.
- Putting an item back within 10 minutes of the tick counts as the tick's undo; later it counts as a new add for analytics only. The user sees no difference.
- No code path purges ticked items after a time (none found); the section keeps the 20 newest. unverified (no server job found, not run).
- Without `add-sheet-compact`, the „Rückgängig“ in the add note disappears at the next keystroke; click it before typing again.
- Ticking has no undo snackbar since the job 29b release; old recipes that wait for a „Rückgängig“ after a tick are wrong.
- Rows are role `checkbox` since job 57 (2026-11-01): `itemRow` in `e2e/tests/helpers.ts` and `helpers/lib.mjs` find them that way; recipes that look for a row as `button` find nothing. Rows under „Zuletzt verwendet“ stay buttons (`usedRow`).
- `tick` waits for the row to go; the row needs about 440 ms before the tick commits, so an add of the same name right after a click finds it still on the list.
- A reload right after a click keeps the tick since job 222, but the write goes out only after the reload, from the device's queue: `tickSaved` still is the helper that waits for the PATCH. A tick made less than 440 ms before signing out goes with the device's data (by design: sign-out forgets the queue).
- On web the commit of a hidden row rests on `visibilitychange`: Flutter 3.50's web engine tells the app of a hide through the document's `visibilitychange` and the window's `focus` and `blur`, nothing else (`app_lifecycle_state.dart` in the engine; no `pagehide`, no `beforeunload`). A closing Firefox tab ends the script that runs at that moment and the app then runs no `await` any more, so what the hide saves may never be written (job 222 review 1: 4 lost ticks in 108 closed tabs in CI). Whatever must survive a closed tab is saved when the user acts, as the tick is at the tap; the hide is not the place.

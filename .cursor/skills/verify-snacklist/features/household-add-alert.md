# Household add alert (flag `push-household-add`, off; job 377; the name switch has no flag since job 479)

Under Mehr → „Benachrichtigungen & Erinnerungen“ / "Notifications & Reminders" (its own More page since job 463, renamed in job 472, `/more/notifications`; a section of Einstellungen before), in phone builds with push, the switch „Wenn jemand etwas hinzufügt“ / "When someone adds something". On (it is off for everyone until they switch it), the user gets a push when another household member adds an item: „Lea hat Milch hinzugefügt“ / "Lea added milk" (the item name as entered). Several adds within a few minutes come as one: „Lea hat 4 Einträge hinzugefügt“ / "Lea added 4 items". A tap opens that household's list. Not on the web (no web push). Needs the server switch `push_household_add`, which stays off until Legal's GO. The privacy policy's push section is live since 26 November 2026 (snacklist.app/datenschutz#mitteilungen; hold `push-notifications` released).

## Sub-features

- `ha-switch` the switch, off by default; turning it on asks the OS for notification permission, a refusal leaves it off with the snackbar „Mitteilungen sind für Snacklist ausgeschaltet. Erlaube sie in den Einstellungen deines Geräts.“ / "Notifications are turned off for Snacklist. Allow them in your device's settings."; a save that does not reach the server leaves the switch as it was with „Die Änderung konnte nicht gespeichert werden.“
- `ha-self` nobody is pushed about their own adds, on any of their devices.
- `ha-batch` an add goes out 2 minutes after the last add of that person to that list, at the latest 5 minutes after the first; several become one count line, unless one of them is a pharmacy or drugstore item (`ha-private`).
- `ha-trip` no push for adds made while the adder shops: within 10 minutes of their own app tick (trip detection's "a trip may still be going on" rule; the running trip of trip mode is only on the device).
- `ha-private` items of the Drogerie category or from a pharmacy or drugstore (dm, Rossmann, Kruidvat, Müller, Budni, pharmacy words) are never named: „Lea hat etwas zur Liste hinzugefügt“ (EN "Lea added something to the list"); a batch holding any such item reads the same, with no count; only a batch of ordinary items is a count.
- `ha-name` (on every platform, the web included, with no flag since job 479, Legal N-425) the second switch „Meinen Namen in Mitteilungen weglassen“ / "Leave my name out of notifications": others then read „Jemand hat …“ / "Someone added …". It shows with `push-household-add` off, so a member the flag has not reached yet can object before members it has reached name them. While the saved choice is read, a small spinner („Lädt …“ / "Loading…" to screen readers) stands where the switch goes. When it cannot be read, the page shows „Konnte nicht geladen werden.“ / "Couldn't load." with „Erneut versuchen“ / "Try again" instead of the switch; while a retry runs that line stays and the button is greyed out.
- `ha-off` turning the switch off also removes this phone from push, as signing out does, unless another push type is still on for the person: while a weekday of the [shopping-day reminder](./shopping-day-reminder.md) is picked, the phone stays registered.
- `ha-readd` an item put back from „Zuletzt verwendet“ later than 10 minutes after its tick counts as an add; an item that arrives ticked, a delete's undo and a tick's undo do not.
- `ha-tap` a tap opens the list (P0's deep link).

## How to get to it (user POV)

- Mehr → „Benachrichtigungen & Erinnerungen“ / "Notifications & Reminders", the row after „Einstellungen“; on the page the first group, with no label of its own (the page title says it), before „Einkaufstag-Erinnerung“. Everybody sees the row and „Meinen Namen in Mitteilungen weglassen“ (no flag, job 479); the add switch above it needs the flag and a phone with push, so today nobody sees that one (flag off; PostHog shows it to internal installs only, `releases/flags.json`). On the web the page shows only the name switch. A tap moves either switch at once; a save the server refuses, or notifications refused by the OS, puts it back with a notice („Die Änderung konnte nicht gespeichert werden.“ or „Mitteilungen sind für Snacklist ausgeschaltet. …“). Quick taps are saved in their order.

Preconditions: a plain `helpers/launch.sh` for the name switch (since job 479 it needs no flag); none of the household-add sections sit in Einstellungen.

- Name switch: `openMore(page, 'Benachrichtigungen & Erinnerungen')` → switch `/^Meinen Namen in Mitteilungen weglassen/`, toggle it, read `push_preferences.name_hidden` through `apiAs` (own row only). No „Wenn jemand etwas hinzufügt“ on the web. Driven 2026-11-28 on 15145842 (vmaint-20261128, `journeys/more-help.mjs`, DE and EN): the row after „Einstellungen“ on a plain launch and with `FLAGS_ON=push-household-add,push-shopping-day,push-shopping-reminders`, the page with only the name switch on both. Driven 2026-11-27 (job 479b, plain launch, DE and EN) on main bb48a231 plus this change: with the `push_preferences` read held the page shows the spinner, labelled „Lädt …“ / "Loading…", and no switch and no failure line; with the read aborted (the client tries three times, about 7 s) the failure line and an enabled „Erneut versuchen“; with the retry's read held the line stays and the button is `aria-disabled`; let through, the name switch shows. Driven 2026-11-27 on the code pushed as f6b29954 (job 479's fix round after review 1, plain launch, DE and EN): More lists „Mitteilungen“, the page shows only the name switch, a tap saves `name_hidden` both ways; with `rest/v1/push_preferences` aborted the page shows „Konnte nicht geladen werden.“ (a group of that name around the button) and „Erneut versuchen“, no switch, and the retry with the read let through shows the switch with the server's value. Driven 2026-11-27 on 72516831 with `VH_DEFINES="FLAGS_ON=push-household-add"` on the own More page: „Mitteilungen“ right after „Einstellungen“, `/more/notifications` with the name switch only, which moved at once and saved `name_hidden`; Einstellungen without it. On a plain launch: no row, and `/more/notifications` opens Mehr. Driven 2026-11-26 on ba89a099 (job 479 review 0) with a plain launch and again with `VH_DEFINES="FLAGS_ON=push-household-add"`: More lists „Mitteilungen“, the page shows only the name switch, a tap sets `name_hidden` true and a second tap false, and `/more/notifications` opens the page. Earlier: 2026-11-23 on d023441d with both push flags, before #726, in the old layout (a „Mitteilungen“ section of Einstellungen).
- The add push itself is not drivable in the web build (no FCM there). The decisions run in SQL: `supabase/tests/push_household_add.test.sql` (`supabase test db`), and the switch in `app/test/push/household_add_alert_test.dart`. The send path through pg_net to the `push` function is `public.push_add_flush()`; on the local stack it answers 503 `not_configured` without `PUSH_SEND_SECRET` (docs/PUSH.md, "Household add").

## Gotchas

- The add push needs both the PostHog flag and the server switch `push_household_add`; with only the flag the switches save but nothing is sent. The name switch needs neither to show and save; the server honours `name_hidden` in every push it builds.
- The push and the tap are unverified on a device.

# Onboarding: from first sign-in to the list

After the first sign-in a user without a household lands on „Willkommen bei Hummlist“ / "Welcome to Hummlist" and either creates a household or accepts an invite. Creating asks for a name (prefilled „Unser Haushalt“ / "Our household") and which stores the household shops at (eleven common ones to pick, the last a „Baumarkt“; own ones to type; or none), then offers to invite the partner, then opens the list. Opening an invite link skips the choice and goes to the join screen after sign-in (on the web `/join/<code>` is the static join page, whose „Im Browser beitreten“ opens the app at `/?invite=<code>`; household-invites `join-page`). Builds that carry analytics ask the analytics question first (feature privacy-consent).

## Sub-features

- `welcome` Step 1, title „Willkommen bei Hummlist“ / "Welcome to Hummlist", text „Hummlist teilt eine Einkaufsliste mit allen in deinem Haushalt. Erstelle einen neuen Haushalt oder nimm eine Einladung an.“ / "Hummlist shares one shopping list with everyone in your household. Create a new household or accept an invite." Two cards: „Haushalt erstellen“ (hint „Eine neue Liste, zu der du danach deinen Partner einlädst.“) / "Create a household" ("A new list; you invite your partner next.") and „Einladung annehmen“ (hint „Du hast einen Link oder einen Code bekommen.“) / "Join with an invite" ("You got a link or a code."). Above the text the Hummlist icon and wordmark. Below: „Konto löschen“ / "Delete account" (red text button); in the app bar a logout icon, tooltip „Abmelden“ / "Sign out".
- `create` Step 2a, title „Haushalt erstellen“ / "Create a household": field „Name des Haushalts“ / "Household name" (prefilled „Unser Haushalt“, 1 to 80 characters, error „Gib einen Namen mit 1 bis 80 Zeichen ein.“ / "Enter a name of 1 to 80 characters."), group „Läden“ / "Stores" with the hint „Wähl die Läden, in denen ihr einkauft. In dieser Reihenfolge stehen sie in der Liste.“ / "Pick the stores you shop at. Your list shows them in this order.", eleven filter chips (EDEKA, REWE, Lidl, Aldi Süd, Aldi Nord, Kaufland, Netto, Penny, dm, Rossmann, Baumarkt; „Baumarkt“ is a store type, not a chain, and brings the seven Baumarkt categories (job 151, feature categories `cat-baumarkt`); none picked; `app/lib/household/popular_stores.dart`), the button „Eigenen Laden hinzufügen“ / "Add your own store" (plus icon; an inline field „Name des Ladens“ / "Store name"; a typed store joins the chips, picked; a typed name of an offered chain in any case or spacing, „edeka“ or „ EDEKA “, ticks that chip instead, and a name already picked stays picked once), the store-name note „Ladennamen wie dm, Lidl oder EDEKA verwenden wir nur, …“ / "We use shop names such as dm, Lidl or EDEKA only so you can see which shop a list is for. …", the button „Haushalt erstellen“ / "Create a household", then „Überspringen“ / "Skip" (creates it without stores) with the hint „Ohne Läden starten. Du kannst sie später unter Liste → Anpassen anlegen.“ / "Start without stores. You can add them later under List → Edit." (Liste → Anpassen has „Laden hinzufügen“ since job 78). The picked stores are created in the order picked. The creator becomes the owner. A double tap or a retry after a lost answer makes one household.
- `invite-step` Step 3, title „Partner einladen“ / "Invite your partner" (`/welcome/invite`): text „Teile den Link oder den Code mit der Person, mit der du einkaufst. Die Einladung gilt 7 Tage und für eine Person.“ / "Share the link or the code with the person you shop with. The invite is valid for 7 days and for one person." Button „Partner einladen“ makes an invite (card with code, link, expiry and share/copy buttons, see household-invites); „Später“ / "Later" goes to the list, after an invite is made the same button reads „Weiter zur Liste“ / "Go to the list".
- `join` Step 2b, title „Einladung annehmen“ / "Join with an invite" (someone already in a household sees „Haushalt beitreten“ / "Join a household"): field „Einladungscode“ / "Invite code", button „Weiter“ / "Continue" shows the household's name under „Einladung in den Haushalt“ / "Invite to the household", then „Haushalt beitreten“ / "Join household" (cancel: „Abbrechen“ / "Cancel"). Details in household-invites.
- `invite-link` an invite (`/?invite=<code>` on the web, `/join/<code>` in the apps) survives sign-in, the analytics question and onboarding steps (kept for 7 days on the device); a new user lands on the join screen with the code filled in and the household previewed.
- `offline` create and join say „Keine Internetverbindung. Versuche es erneut, sobald du online bist.“ / "No internet connection. Try again once you're online." and keep what was typed.

## How to get to it (user POV)

- Sign up or sign in with an account that has no household: the app goes to Step 1 by itself (after the analytics question on builds with analytics).
- Open an invite link signed out: sign in, then the join screen opens directly.
- Step 1 „Haushalt erstellen“ → Step 2a → Step 3 → list. Step 1 „Einladung annehmen“ → join screen → list.
- Back arrows return to Step 1 (no household) from Step 2a and the join screen.

## Driving it with Playwright

Preconditions:

- Local stack, web build, a fresh email per run (`newEmail(...)` in the specs) because the seeded users already have a household. Viewport 390x844 or 480x900.
- On the e2e build the analytics question comes first; `signUp(page, email)` signs up and answers it (decline by default).

- **Sign up to Step 1.** `signUp(page, email)`. Observable result: URL `/welcome`, buttons `page.getByRole('button', { name: /^Haushalt erstellen/ })` and `/^Einladung annehmen/` visible.
- **Create with the specs' stores.** `createHousehold(page)` (clicks the card, optionally types a name with `typeInto(page.getByRole('textbox', { name: 'Name des Haushalts' }), name)`, then for each of `stores` ticks an offered one such as `page.getByRole('checkbox', { name: 'dm', exact: true })` and types any other as an own store (button „Eigenen Laden hinzufügen“, textbox „Name des Ladens“, Enter), and clicks `page.getByRole('button', { name: 'Haushalt erstellen', exact: true })`). Observable result: URL ends `/welcome/invite`; via the API second view: one household named „Unser Haushalt“, the user as only member with role owner; with `createHousehold(page, { stores: chainStores })` the stores dm, Lidl, EDEKA in that order (`createHousehold(page)` alone clicks „Überspringen“ and makes none).
- **Pick and type stores.** Tick `page.getByRole('checkbox', { name: 'REWE', exact: true })`, click „Eigenen Laden hinzufügen“, `typeInto(page.getByRole('textbox', { name: 'Name des Ladens' }), 'Wochenmarkt')`, Enter. Observable result: `page.getByRole('checkbox', { name: 'Wochenmarkt' })` checked; after „Haushalt erstellen“ the stores are REWE, Wochenmarkt.
- **Type an offered chain.** Click „Eigenen Laden hinzufügen“, `typeInto(page.getByRole('textbox', { name: 'Name des Ladens' }), 'edeka')`, Enter. Observable result: `page.getByRole('checkbox', { name: 'EDEKA', exact: true })` checked, no checkbox „edeka“; a click unchecks it; after „Haushalt erstellen“ the household has one store EDEKA (seed_key edeka), or none if unchecked.
- **Create without stores.** `createHousehold(page, { stores: [] })` clicks `page.getByRole('button', { name: 'Überspringen', exact: true })` (below it the text „Ohne Läden starten. Du kannst sie später unter Liste → Anpassen anlegen.“). Observable result: household without stores, 11 categories.
- **Invite step.** `page.getByRole('button', { name: 'Partner einladen', exact: true }).click()`; the card shows (`inviteCodeLabel(page)`, text „gültig bis …“). Leave with `skipInvite(page)` (button `/^(Später|Weiter zur Liste)$/`): URL `/`, `addField(page)` focused.
- **Join with a code.** `joinWithCode(page, code, 'Familienname')` (clicks „Einladung annehmen“ if on Step 1, types into textbox „Einladungscode“, „Weiter“, then `confirmJoin`: button „Haushalt beitreten“). Observable result: URL `/`, `addField(page)` visible; the preview text for the household name is checked with `invitePreview`.
- **Invite link before sign-in.** `signUp(page, email, invitePath(code))` then `confirmJoin(page, household)`; through the static page: `openJoinLink(page, '/join/' + code)` (URL `/login?invite=<code>`), `signUpHere(page, email)`, `confirmJoin` (driven 2026-11-08, `invite-loop.spec.ts`, onboarding AC1).
- One-shot helper: `signUpWithHousehold(page, email)` = sign up, create without stores, skip the invite (`{ stores: chainStores }` for dm, Lidl, EDEKA).
- Covered by `e2e/tests/onboarding.spec.ts` (AC1-13, including invite link through password, magic link and fake Google/Apple, offline, rate limit, English), `e2e/tests/analytics.spec.ts` (order: sign-in, consent, onboarding), `app/test/household/onboarding_test.dart` (typed chain names tick the chip, the skip hint). Run via `scripts/verify.sh --only e2e -- tests/onboarding.spec.ts`.

## Gotchas

- There is no separate "store step" or "email opt-in" in onboarding: the stores choice is the chips (checkboxes on the web) on the create screen; the app asks for no newsletter or email opt-in anywhere in this flow (searched the screens; nothing found).
- The seeded demo users are already onboarded, so a recipe needs a fresh sign-up to see Steps 1-3.
- The prefilled household name is not in the DOM until the field is edited (so `toHaveValue` on it fails); edit with `typeInto` or just click create.
- Step 3 on the web shows the invite card (code, link, copy buttons) and only the „Teilen“ button where the browser has Web Share; Chromium in Playwright has none. The phones open the share sheet at once.
- Someone already in a household who opens an invite gets no warning since job 169b: joining adds the household and keeps theirs.
- Back or „Abbrechen“ on the join screen forgets a pending invite link.
- Too many wrong codes (10 failures in an hour) show „Zu viele Versuche. Bitte später noch einmal.“ / "Too many attempts. Please try again later." even for a valid code.
- Fake-OIDC e2e specs (provider sign-in lands on the join screen) need the fake issuer reachable from the Supabase container and time out on the Hetzner boxes; trust CI for them.

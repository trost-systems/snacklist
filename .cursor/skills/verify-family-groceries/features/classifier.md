# Classifier

Every new item lands in a category without the user choosing one, unless they pick one on the add sheet's category chip. The list groups items under small category dividers: inside a store in that store's order, under "Ohne Laden" in the household's route order (Obst & Gemüse first, Sonstiges last). The user can move an item to another category in its edit sheet, and the household remembers the move: the next time that item is added, it lands in the category it was moved to. A category picked on the add sheet is remembered the same way, and "Rückgängig" on that add forgets it again. Classification runs on the server (`classify_item`: learned corrections, then a German dictionary of about 1200 terms, spelling variants, synonyms and typos (job 32a), then "Sonstiges"), so the app, MCP, Siri and voice agree. The add sheet's category chip shows the guess while the name is typed, and the item also gets a store guess: the remembered store, else a store's own brand (Balea → dm), else dm for drugstore items when the household has dm.

## Sub-features

- `cls-auto` puts a new item under a category divider from the dictionary, including compound endings ("Ziegenmilch" → Kühlregal, through "milch").
- `cls-baumarkt` DIY words (about 250, job 151) go to the Baumarkt categories when the household has a Baumarkt ("Schrauben" → Schrauben & Befestigung, "Glühbirne" → Elektro & Leuchtmittel), else to Haushalt; pgTAP `hardware_categories.test.sql` classifies 56 of them both ways.
- `cls-fallback` puts an unknown item under "Sonstiges", shown last.
- `cls-order` shows the dividers of "Ohne Laden" in route order (uppercase, without the emoji): Obst & Gemüse, Brot & Backwaren, Kühlregal, Fleisch/Wurst/Fisch, Vorrat & Konserven, Süßes & Snacks, Getränke, Tiefkühl, Haushalt, 👶 Drogerie, Sonstiges.
- `cls-move` moves an item to another category through the edit sheet's category chip ("Fertig").
- `cls-learn` puts a re-added item into the category it was last moved to, also when it is re-added before the move reached the server: the add sends no category unless one was picked, so the server classifies it after the move (job 126).
- `cls-picked` learns a category picked on the add sheet's chip (`chip-category`) when it differs from the guess (`categorized_via` `picked`); the note's "Rückgängig" (`added-undo`) within 10 minutes removes the item and that lesson. With `add-feedback-list` the pick comes after the add, in the details, as an edit; "Rückgängig" deletes through `undo_add` and takes that edit's lesson back too (job 315), while any other delete keeps what an edit taught.
- `cls-variants` puts a misspelling, a regional word or an English word with the word it means ("Karrotten", "Paradeiser", "Semmeln", "Schokolde", "toilet paper"); the name stays as typed (job 32a).
- `cls-variant-learn` sends a word's spellings and synonyms where the household moved one of them ("Karrotten" moved to Getränke, then "Möhren" lands there), in that household only.

## How to get to it (user POV)

- Add an item in the add bar at the bottom of the list. Without a store it appears under its category divider in "Ohne Laden".
- Hold the item without moving (or right-click it) to open the edit sheet, tap the category chip, pick another category from the options that fold out, and tap "Fertig".

## Driving it with fg

Preconditions:

- Baseline from `features/README.md`; peter signed in on the list.
- The test items are not active and have no store memory. Ziegenmilch and Xylophon land in "Ohne Laden"; Windeln, a drugstore item, lands in dm (the dm guess): `fg db query "update items set status = 'bought' where status = 'active' and name in ('Ziegenmilch', 'Windeln', 'Xylophon')" --write`. Seeded runs share the stack, so read with `--as peter`.

- **Auto-categorize.** Run `fg type --key add-item-field --input Ziegenmilch --submit`, then the same for `Windeln` and `Xylophon` (the sheet stays open between them), then `fg press escape`. `fg wait --text Xylophon` succeeds. `fg find --type Text` lists DROGERIE with Windeln under dm, then "Ohne Laden" with KÜHLREGAL and SONSTIGES, each item after its divider. The stored view: `fg db query "select i.name, c.name as category from items i join categories c on c.id = i.category_id where i.status = 'active' and i.name in ('Ziegenmilch', 'Windeln', 'Xylophon') order by i.name" --as peter` returns 👶 Drogerie, Sonstiges and Kühlregal.
- **Divider order.** In "Ohne Laden", the `y` bounds of the divider texts in `fg find --type Text` increase in route order. SONSTIGES is the last divider, above "Zuletzt verwendet".
- **Move.** Run `fg marionette -- long-press --text Xylophon`, then `fg wait --key edit-sheet` (the sheet is open). Run `fg tap --key chip-category` (`chip-store` is the store chip), `fg wait --key category-option-<Süßes & Snacks id>` (`fg db query "select id from categories where name = 'Süßes & Snacks'" --as peter`), `fg tap --key category-option-<id>`, `fg tap --key edit-done` and `fg wait --key edit-sheet --gone`. `fg wait --text "SÜSSES & SNACKS"` matches (ß turns into SS on the divider), Xylophon shows under it, and the category query above returns that category for it. `fg db query "select c.name, m.corrections from category_memory m join categories c on c.id = m.category_id where m.item_key = 'xylophon'" --as peter` returns Süßes & Snacks with a count.
- **Learn.** Tick Xylophon (`fg tap --text Xylophon`, then `fg wait --text Xylophon --gone`) and add it again with `fg type --key add-item-field --input Xylophon --submit` and `fg press escape`. It lands under "Süßes & Snacks". `fg db query "select c.name from items i join categories c on c.id = i.category_id where i.name = 'Xylophon' and i.status = 'active'" --as peter` returns Süßes & Snacks.
- **Variants.** Run `fg type --key add-item-field --input Karrotten --submit`, then the same for `Paradeiser`, `Semmeln`, `Schokolde` and `toilet paper`, then `fg press escape`. Each shows under its divider (OBST & GEMÜSE, BROT & BACKWAREN, SÜSSES & SNACKS, HAUSHALT) with its name as typed. `fg db query "select i.name, c.name as category, i.categorized_via, i.canonical_key from items i join categories c on c.id = i.category_id where i.status = 'active' and i.name in ('Karrotten', 'Paradeiser', 'Semmeln', 'Schokolde', 'toilet paper') order by i.name" --as peter` returns, in that name order (Karrotten, Paradeiser, Schokolde, Semmeln, toilet paper), via exact, synonym, fuzzy, exact, synonym; Karrotten's canonical key is `mohr`, the same as `select canonical_key('Möhren')`. Take `fg screenshot --name cls-variants`.
- **Picked on the add sheet.** Run `fg type --key add-item-field --input Zither` (no `--submit`), `fg wait --text "Zither, Wie getippt"`, `fg tap --key chip-category`, `fg tap --key category-option-<Getränke id>` and `fg press enter`. `fg db query "select categorized_via from items where name = 'Zither' and status = 'active'" --as peter` returns `picked`, and `fg db query "select c.name, m.corrections, m.undo_item is not null as undo from category_memory m join categories c on c.id = m.category_id where m.item_key = item_key('Zither')" --as peter` returns Getränke, 1, true. Tap `fg tap --key added-undo`: the memory query returns no rows, and Zither added again without the chip lands in Sonstiges (`fallback`).
- **Variant learn.** Move Karrotten to Getränke as in **Move**, then add `Möhren`: it lands under GETRÄNKE, and the query above for it returns via `household`. Take `fg screenshot --name cls-variant-learn`.
- **Proof.** Take `fg screenshot --name cls-after-add` and `--name cls-after-move`, and save the category query output for both states.

## Gotchas

- The category options carry keys (`category-option-<id>`); tap them by key. Their names also appear as divider labels on the list behind the sheet.
- Divider texts are uppercase and drop a leading emoji ("👶 Drogerie" reads DROGERIE, "Süßes & Snacks" reads SÜSSES & SNACKS); the full name is the divider's semantics label.
- Household and drugstore goods (bags, cleaning brands, Kleber, Taschentuch) are covered since job 2b: "Mülltüten" → Haushalt, "Sekundenkleber" → Haushalt (not Fleisch via "leber"), "Elmex" → Drogerie. A quick check: `fg db query "select c.name from categories c where c.id = classify_item((select id from households where name = 'Familie Test'), 'Mülltüten')"` returns Haushalt.
- `supabase/classifier/sweep.sh` reruns the 345-item non-food sweep (`sweep.tsv`) on the checkout's own stack (the `project_id` in `supabase/config.toml`, not an `fg` instance) and prints every item whose category moved; it exits 1 if any did. Run it after a dictionary change; refresh the list with `sweep.sh --print` only when the move is intended.
- Matching folds case, umlauts and one plural ending ("Gurken" = "Gurke") and prefers the head of a compound ("Ziegenmilch" → Kühlregal, "Milchschokolade" → Süßes & Snacks). Common compounds such as "Vollmilch" and "Hafermilch" are dictionary terms of their own, so they don't prove compound matching. The dictionary is `supabase/classifier/dictionary.tsv`.
- Item names fold numbers away: after a move of "Xylophon", "Xylophon-123" lands in the learned category too. Use distinct words, not numbered variants, when the first category matters.
- Learning is per household and survives `fg up` but not `fg up --fresh`. A move taught in an earlier run changes where the item lands. Start from `--fresh` when the first category matters.
- Online adds show under the add sheet's guessed category at once; the server classifies them again on insert, so the row can move when the answer comes (a correction just before). An item added without one (offline, or Enter before the sheet had an answer) shows under "Wird einsortiert …" until the server returns the category. Wait with `fg wait --contains "Wird einsortiert" --gone` before you assert.
- Renaming an item in the edit sheet keeps its category; the classifier runs on adds (and on rows left without a category), not on renames.
- A new item that store memory knows lands in that store's section, not in "Ohne Laden"; its category divider then follows the store's order.
- `supabase/classifier/wordlist.sh` and `latency.sh` (job 32a) print the word list's rates (misspellings right, false matches) and the classifier's p50/p95 against the one before job 32a, on the checkout's own stack; the db gate runs them, and `client_catalog.sh --check` (the catalog the app bundles, `app/lib/list/catalog/catalog_index.g.dart`: terms, word forms, brands and the parser's units and number words, for trailing counts, the category guess and on-device suggestions; jobs 61, 272, 274). `CLASSIFIER_PSQL="psql -h … -d …"` points them at another database. Synonyms are `supabase/classifier/synonyms.tsv` (`generate_synonyms.ts`); a dictionary or synonym migration ends with `refresh_classifier_lexicon()`.
- Typo matching is deliberately shy: never under 5 letters, the same first letter; two 5-letter words only by swapping neighbouring letters ("Mlich"), one edit when the longer word has 6 letters or more, two when both have 8 or more; and only when the nearest words agree on a category. "Mehk" or "Kaffe" stay in Sonstiges; that is intended, not a bug.
- The edit sheet's fields have keys (`edit-name`, `edit-quantity`, …; `features/edit-item.md`).

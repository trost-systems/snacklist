# Add sheet: add feedback and reload indicator prototypes (job 273)

A throwaway HTML sandbox for two decisions about the add sheet. Nothing here ships; the app is unchanged. Demo data only (the fictional Brandt family), no network calls.

- `add-feedback/`: round AF. After a tap in the add sheet, how does the user see which item went to which store and section, and find or fix it after the close? Today (main) and AF1–AF5. `RECOMMENDATION.md` (and `.de.md`): the pick (AF3), the runner-up (AF5), AF-Q1 to AF-Q6.
- `reload-indicator/`: round RI. How does the sheet show that server suggestions are still loading, without rows jumping under the finger? Today, the control “272 base, no indicator” and RI1–RI3. `RECOMMENDATION.md` (and `.de.md`): the pick (RI2), the runner-up (RI1), RI-Q1 to RI-Q6.

Each page shows only its own round: every option as two live phones side by side (AF: the sheet open after the scenario’s adds, and just after the close; RI: typed fast with the reply on the way, and the reply landed), the measured table and the recommendation. Controls: the scenario (AF: one known item, three adds in two stores, long names, a first-time grocery, an add into an empty section, fix then add again; RI: the reply time 450, 150 or 1800 ms, plus “Play fast typist” and “Play slow reply”), English or German (`?lang=de`), light or dark (`?theme=dark`), text at 100 % or the largest the prototypes test, 200 % (`?ts=200`), and for RI reduced motion (`?motion=reduce`). The phone is 390 × 844; below 440 px wide one phone fills the screen and a strip switches between them.

## Files

- `model.js`: the stores (Lidl, Rewe, dm, “Wochenmarkt am Kollwitzplatz”), categories, the catalog (the classifier stand-in, EN and DE), the open list, the household memory, history and usuals, the suggestion engine (`serverRows` like `suggest_entries`: the typed row, up to 3 history and 3 catalog rows, each with parse_item’s or guess_store’s store, the remembered one, else dm for drugstore items; `deviceRows` like `_offline`, without a store; `emptyRows`: due, then recent usuals) and ST1 (`usualStore`: the most-used store for the category over the list and the memory). App strings come from `app/l10n/app_*.arb`.
- `sandbox.js`: the phone. State: the list, memory, history, the add records of this session, the sheet (text, rows, the answer they belong to, chip picks, the note), the fix picker, the “Learned” line and the edit sheet. Actions: open, type (instant, or with today’s 120 ms debounce and a reply latency: the first letter on the device, later letters keep the previous rows until the reply), take, Enter, undo, correct (moves the row, writes the memory), buy, close. Today is the phone with no option slots; an option fills slots (`note`, `confirm`, `sheetTop`, `float`, `bar`, `rowExtra`, `onAdd`, `onClose`, `fieldTrail`, `sheetEdge`, `rowClass`, …). Today mirrors main: the store comes from the tapped row or the server’s memory, the note names a store only when the row knew it (a server row, typed rows included, knows it as `suggest_entries` does; a row built on the device does not), a first-time grocery gets no store; the options use memory, then ST1. An option may set `half` and `scrim` per phone (AF5 is a half sheet only below 130 % text).
- `add-feedback/options.js`, `reload-indicator/options.js`: the options as slot sets, the scenarios, the frames and each option’s fix paths (the controls a fix goes through, which the verify script clicks and counts).
- `page.js`, `proto.css`: the round page. `icons.js`: Material glyphs from Flutter’s icon font (`tools/icons.py`). Tokens and fonts come from `site/public/`.
- `verify.mjs [<folder or url>] [<out>] [<playwright dir>] [--write]`: drives both pages in Chromium. It measures every table column with real clicks, DOM checks and pixel diffs (identifiable while open in the text a reader sees, at 100 % and 200 %; several adds; find after the close, also once AF2’s bar or AF4’s toast has gone; fix store and section while open, after and late, and what the option’s feedback (note, tray, card, toast, row chip, Learned line) shows after each fix: the new store or section, never the old one; the correction sticking for a typed re-add; extra height; text cut by a clip or an ellipsis, spilling or overlapping at 200 %, the option’s own apart from main’s chrome; whole rows after the close and list text half under a toast; suggestion rows while typing and right after an add; RI, in English and German at 100 % and 200 %, each cell the worst of the four with where it holds: the indicator on every animation frame of the fast-typist play, gone in the reply’s frame, height and row moves, a tap during a slow reply, the pixels the indicator changes and by how much, 200 %, reduced motion), checks Today’s note against main (Enter on “Eggs” shows “→ Lidl”, “Soap” “→ dm”), ST1 in “first”, the new Frozen section in “empty”, three adds in “several”, nothing of the list through the add band, the reason on its own line, a scrolled-to row whole with its header, 44 px targets, hex content centred, the option’s chip labels reading as one run of text (no piece beside or above the one before it), page errors, English by default and German with `?lang=de` (no “Bereich”), only the round’s own controls, the questions, the pick and runner-up (`round.rec`) against the page’s tags, the starred row, the page’s headings and both RECOMMENDATION files, the back link (and, in a build with the overview, overview → round → back), and writes the screenshots (every option and scenario, EN/DE × light/dark × 100/200 %, the 390 px view) into `<out>`. It compares the measurements with `<round>/measured.json` and the tables in both RECOMMENDATION files; `--write` updates them. The last line is `all checks passed (N)`; any miss exits 1.
- `tools/probes.js`: the in-page checks the verify script uses. `tools/serve.mjs`: a static server on 127.0.0.1 for the verify script (not a preview).
- `build.sh <out> [<list-declutter dir>] [<feedback-experience dir>] [<household-onboarding dir>]`: the static folder for the preview, with #414’s overview at the root and the earlier rounds beside ours in `<out>/add-sheet/`.

## Run

From the repo root: `node docs/design/add-sheet/verify.mjs` (serves the repo). For the preview: `bash docs/design/add-sheet/build.sh /tmp/dist <#414>/docs/design/list-declutter <260>/docs/design/feedback-experience <263>/docs/design/household-onboarding`, then `node docs/design/add-sheet/verify.mjs /tmp/dist`. The overview links to the two pages need an entry each in #414’s `rounds.js` (`linked`), with `href: '../add-sheet/add-feedback/'` and `'../add-sheet/reload-indicator/'`.

## How taps are counted

Every tap counts one, the tap that opens a picker included; holding a row (to open the edit sheet) counts one. A fix after the close without a control of its own goes through the edit sheet: hold, store or category chip, pick, Done (4). Typing and scrolling count no taps; “find after the close” reports the scroll distance instead.

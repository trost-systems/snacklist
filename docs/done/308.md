# Job 308: main reuses its PR's CI run, native gates nightly (OC1 + R3, 2026-11-18)

CI, workflows and docs only, no app code. Decisions: `docs/DECISIONS.md`, job 308. How it works:
`docs/CI.md`, "Main and the nightly run".

## What changed

- `scripts/ci-main-reuse.sh <commit>`: `reuse=true` when a merged PR into main has the commit, the
  PR head has its tree and its single parent, and the newest `ci-ok` on the head passed. Anything
  else is `reuse=false`. Tested in `scripts/ci-main-reuse-test.sh` (lint gate) with a `gh` stub, 15
  cases; making the script ignore a second parent, or read the oldest `ci-ok`, fails it.
- `ci.yml`: on a push, `changes` asks the script. Reuse turns every switch off and skips lint,
  site and site-agent; otherwise the commit's range decides, like a PR (R3: native only for native
  paths). A `schedule` run at 01:17 UTC runs every gate; `nightly-report` keeps one issue open
  while nightly runs are red.
- `release.yml`: a run after a CI run that was no push (nightly, dispatch) ships nothing and now
  queues in its own concurrency group, so it can't replace a pending Release run that ships.
- `scripts/e2e-durations.sh` reads the nightly runs first.

## Self-review before landing (`review.self.md` in the job dir, VERDICT FIX, fixed)

- The test's `gh` stub now answers only the exact three requests. Mutations caught: `ci-ok` asked
  as `gitleaks`, the head read as main's commit, a second parent ignored, the oldest `ci-ok`
  read, the merged-into-main filter dropped.
- Comments in `ci.yml` and `docs/CI.md` no longer say a main push never runs native gates.
- A manual run on main no longer cancels the nightly one (concurrency group per run).

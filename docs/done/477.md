# Job 477: the policy date line comes from `updated:` (FL6)

PR: https://github.com/trost-systems/snacklist/pull/754 (draft until review; Legal GO on the exact head before merge, no auto-merge).

## What changed

Each legal page's date line ("Stand: 26. November 2026", "Last updated: 26 November 2026") is now
`Stand: {{updated}}` / `Last updated: {{updated}}` in the Markdown. `site/build.mjs` (`withPolicyDate`)
writes the page's `updated:` there in the page's language: `D. Monat YYYY` (de) or `D Month YYYY` (en),
with the day not zero-padded and the month names from a table in `LOCALES`, so the output does not
depend on the ICU data on the build machine. A date bump (Legal N-279) therefore edits one field per
file. Job 476's script can set that field. Git history is not read, because Vercel clones shallow.

The build fails when:
- a legal page has a hand-written `Stand:` / `Last updated:` line that differs from `updated:`;
- `{{updated}}` appears on a page without `updated:` (a legal page lacking `updated:` already failed);
- `updated:` is not a real date. YAML parsed `2026-02-30` as 2 March without an error, so the raw
  front-matter value must now equal the parsed date.

## Decisions

Moved from `docs/DECISIONS.md` (job 477b), where its heading was "Job 477: the policy date line comes from `updated:`".

- **`{{updated}}` in the Markdown, not a template slot.** The date line stays in the policy text where
  Legal reads it, and the bytes around it do not move, so the rendered pages stay byte-identical. A
  soft-wrapped line (privacy.md) also keeps working.
- **Month names in a table, not `Intl`.** `Intl`'s `en` long date is "November 26, 2026", and its output
  depends on the ICU data on the build machine. Twelve names per language are fixed and testable.
- **An agreeing hand-written line still builds.** The brief fails only a line that disagrees, and Legal
  may paste a dated text back. The next date bump would then fail loudly, which is enough.
- **No date from git.** Vercel clones shallow, and the bump stays an explicit edit (N-279). Job 476's
  script sets the one field.
- **The YAML rollover is closed.** js-yaml turns `2026-02-30` into 2 March. Before this job that only
  touched the "Aktualisiert" line on guides. Now `updated:` dates a legal text, so the raw value must
  equal the parsed date.
- **The check covers only the plain date line.** It matches a line that starts with the page's own
  label (`Stand:` on German pages, `Last updated:` on English ones). A date written in bold, inside
  other text, or with the other language's label is not checked (Opus review). The policies have one
  plain date line each, and the brief asks for exactly that line.

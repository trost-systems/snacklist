# Job 462c: the app hand-off on dead invites and before the launch

Follow-up to #731 (job 462), review 1's nice-to-haves 1 and 2.

## What changed

- **Site guides.** „In der App öffnen“ and `open-in-app.js` are rendered on guide pages and guide
  indexes only in the `launch` stage (`site/build.mjs`, `handOff`). In `waitlist` and `beta`
  no page has the link or the script, so an iPhone never reaches Safari's "address is invalid".
- **Join page.** `render` in `app/web/join/join.js` hides the hand-off when the preview says
  `invalid` or `full` (the same `usable` test that hides the code). It still shows while the
  preview loads and for `rate_limited` and `error`.
- Item 3 (one UA fixture for three tests) is not done; `docs/DECISIONS.md` says why.

## Proof

- `site/test/app-links.test.mjs`: in the launch build guides and indexes carry the hidden link
  below the title; the waitlist and beta builds have none on any page. It failed before the
  `build.mjs` change ("/de/anleitungen has no hand-off script") and passes after. `npm test` in
  `site/`: 277 passed.
- `e2e/tests/join-page.spec.ts`, the iPhone hand-off test (extended, to stay inside the e2e budget's test count): an iPhone UA on `invalid`, `full`, `rate_limited`,
  network error and a malformed code. With the old `join.js` it failed at the invalid case
  ("Expected: hidden, Received: visible"); with the fix all 20 join specs pass (chromium).
- Screenshots (iPhone 15, German), `docs/screenshots/462c/`: `guide-waitlist-iphone.png` (no
  link), `guide-launch-iphone.png` (link to `com.snacklist.app://open/de/anleitungen/siri-kurzbefehl`),
  `join-invalid-iphone.png` (no link), `join-ok-iphone.png` (link to `com.snacklist.app://open/join/ABCD2345`).

# Job 476: draft hold-flip PR when legal text merges behind a hold (FL7)

## Why

#643 merged the push privacy text behind the hold `push-notifications` on 23 November. The flip
PR (#710) was opened only on 25 November at 22:39, after Legal's gap report. For two days nobody
owned it. Now the merge opens the flip itself, as a draft.

## What

- `scripts/hold-flip-draft.sh [--dry-run] [--base <rev>] <merged-PR-or-commit>`. It finds the holds
  whose text the merge added or changed: lines of `site/content/legal/*.md` inside `::: once|until
  <hold>` blocks, or under a heading with `once=`/`until=`, up to the next heading of its level.
  It keeps only holds that main still has unreleased. For each one without an open PR on
  `hold-flip/<hold>`, it branches from main and makes the flip: `released` true, plus the date lines
  in the files that hold a block for that hold. It opens a draft labelled `do-not-merge`. Then it
  appends the enable-checklist line to `docs/NEEDS_LEAD.md` (once per hold) and pushes with
  `PUSH_PR_KEEP_DRAFT=1 PUSH_PR_SKIP_CHECKS=1 scripts/push-pr.sh`.
- `scripts/merge-pr.sh`. After the merge it starts the script through `run_detached` (`lib.sh`).
  The child closes every inherited descriptor above 2, so it holds neither merge-lock's flock nor
  the ssh coproc to the Mac. `setsid nohup` runs it with output to `.git/hold-flip-draft.log`.
  merge-pr.sh's exit code and lock time do not change. merge-pr.sh now also refuses any PR labelled
  `do-not-merge`; the label comes off by hand.
- `scripts/push-pr.sh`: `PUSH_PR_KEEP_DRAFT=1` leaves a draft a draft.
- Tests: `scripts/hold-flip-draft-test.sh` (new, lint gate) and three new cases in
  `scripts/landing-test.sh`.
- Docs: `docs/CI.md` "Hold flips after a merge (job 476)", and the landing step in `AGENTS.md`.

## Verification

- `scripts/hold-flip-draft-test.sh`: all cases pass. The fixture repo has a bare origin, a fake gh
  and a stub push-pr.sh, and makes no network calls. The cases: a `once` block opens one draft with
  `--draft --label do-not-merge`, and push-pr.sh runs with keep-draft. The flip changes only
  `released` and the dates of the files with a block. The NEEDS_LEAD line is there once, with the PR
  number. The body has the hashes and the checklist. A rerun by PR number and by commit does nothing.
  A later merge gets one comment on the open PR. A released hold or a merge without legal text opens
  nothing. An `until` block opens the flip of its hold. A heading gate, plus a second hold, in one
  merge opens two drafts. A heading gate ends at the next heading of its level. When main already has
  the line, a reopened flip adds no second one. An unmerged PR is skipped. A dry run pushes and opens
  nothing. `run_detached` frees a flock held by its caller.
- Mutations: with the heading-gate parse dropped, 2 cases fail. With the open-PR check dropped, the
  comment case fails. With the NEEDS_LEAD append dropped, 3 cases fail. One mutation survived (the
  extra check of main's NEEDS_LEAD), which showed that check was redundant, so it is gone.
- `scripts/landing-test.sh`: the new cases pass (keep-draft, `do-not-merge` refused, `do-not-merge`
  refused even with `legal-go`, the hook started after a merge).
- `scripts/verify.sh --only lint`: see the PR.

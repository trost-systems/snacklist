## Harness fixes

**#574, `verify-test.sh` "sed: couldn't flush stdout: Broken pipe".** Cause: `seen_before` in `scripts/verify.sh` pipes `sed` into `grep -Ec "$signal" >/dev/null`. A grep that ends before sed has written all it has leaves sed a closed pipe. Two ways: a signal that is not a regex (the test's own `no-pattern.md` has `(unformatted`, so grep exits 2 at once), and GNU grep itself, which stops at its first match when stdout is `/dev/null`, even with `-c`. With SIGPIPE ignored (the CI shell) sed prints the error, and it landed in the verdict the test compares exactly. Whether it did depended on whether sed wrote before grep exited: a race, so one failure and a green rerun. The comment that claimed `-c` avoided this was wrong. Fix: sed's stderr goes to `/dev/null` and the count is read with `$(...)`. Failing then fixed: the new case in `scripts/verify-test.sh` (a long output whose first line matches, SIGPIPE ignored) fails on main's `verify.sh` (`sed: couldn't write 1 item to stdout: Broken pipe`) and passes with the fix.

**#517, `supabase start` fails with "failed to set up container networking: driver failed programming external connectivity".** The docker daemon on the runner failed to publish a port; no test ran and the rerun passed. `supabase_up` now starts through `supabase_start_retrying` (`scripts/lib.sh`): on exactly that error it runs `supabase stop --no-backup` and starts again, three starts at most; any other failure stops the run at once. `scripts/supabase-start-test.sh` (in the lint gate) covers one error then success, an error that stays (three starts), another failure (one start) and a clean start, with a stubbed CLI. Not reproduced on a real daemon: the error is the daemon's and not repeatable on request, so the proof is the stubbed test.

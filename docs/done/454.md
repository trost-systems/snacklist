# Job 454: T1 shared-axis slide for the onboarding steps

**What changed.** Between the guided start's seven counted steps, the app bar („Schritt N von 7“,
back, X), the progress bar and the step's docked buttons stay still. Only the step's body changes:
it slides 28 dp and fades over 300 ms (`Cubic(0.2, 0, 0, 1)`, 90 ms out, 210 ms in), mirrored on
Back and in RTL. With reduced motion it is a 120 ms crossfade with no movement. Weiter closes the
keyboard in the frame the step changes. Focus goes to the new step's heading.

**How it is wired.**
- Every counted `/start/<step>` route builds a `MaterialPage` with the shared key
  `onboarding-steps` (`onboardingStepRoutes()` in `app/lib/shell/router.dart`, also used by the
  test harness). A step change updates that one page.
- `OnboardingSteps` (`app/lib/onboarding/onboarding_frame.dart`) keeps the chrome and a table of
  each step's back target and X. It switches the body in a `Stack` of the incoming and at most one
  outgoing layer, driven by one `AnimationController` with `AnimationBehavior.preserve`.
- Back is detected from the steps' order: the new step's index in `countedSteps` is lower. That
  covers Zurück, the arrow, Android's back and redirects.
- Reduced motion is `MediaQuery.disableAnimationsOf || MediaQuery.reduceMotionOf`, read when the
  switch starts.
- The incoming layer is a semantics route scope (the web focuses its heading). The outgoing layer
  is excluded from semantics and pointers.
- `OnboardingStepLayout` translates the body only. Its footer is docked above the keyboard.

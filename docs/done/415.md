## What is built

1. **Tool annotations.** One table, `toolAnnotations` in `supabase/functions/mcp/tools.ts`, holds all
   four hints for all 22 tools, explicit booleans. Each tool's `annotations:` reads from it, so a new
   tool cannot ship half-annotated (the table is `Record<McpTool, ...>`). Fixed: `add_items` had none,
   `move_item` defaulted to destructive, no tool had `openWorldHint`, read-only tools lacked
   `destructiveHint`. Decision: `destructiveHint: true` where a call deletes or overwrites text the
   user typed (`remove_items`, `merge_items`, `update_item`, `rename_list`, `rename_store`); false for
   additive writes and for changes that keep every value (ticks, categories, orders). `update_item`
   and the renames moved from false to true. Tests: `tools_test.ts` pins every tool's hints against
   the table and the headline tools literally, and checks each has a title. `add_items`'
   description no longer tells the model what to say. Server version 1.4.0.
2. **ChatGPT compliance.** The locked answer (only while `integration_lock` is on; off in production)
   is now "Dafür brauchst du einen anderen Snacklist-Tarif. Infos: <link> ..." (English by
   `Accept-Language`), with `details.info` in the structured result instead of `unlock: "app"`. No
   plan name, price or call to action; a test checks both languages against a word list. The
   information page exists now: `/de/anleitungen/ki-assistenten-tarif` and
   `/en/guides/ai-assistants-plan` (new guides; the site's content tests list them). It states no
   price and links no checkout. It had not existed before.
3. **Submission pack** in `docs/connectors/` (README with URLs and OAuth details, Claude listing,
   ChatGPT metadata, 5+3 cases, demo shot list, reviewer account). Listings never mention Premium.
4. **Demo account**: `docs/connectors/reviewer-account.md`.
5. **Seed script** `scripts/seed-ai-reviewer.sh <user-id>`: one household, stores dm, Lidl, Edeka,
   IKEA (dm, Lidl and Edeka in their usual sections, IKEA with the default layout), 11 invented items. Proved on a local stack: two runs gave one
   household, 4 stores, 11 open items; a missing user exits 3. It needs `AI_REVIEWER_DB_URL` in the
   environment and contains no credential. Not run against production.
6. **Reviewer login check.** Password sign-in on the consent page needs only email and password; see
   "Sign-in check" in `reviewer-account.md`. No code change needed. Whether production has captcha
   off cannot be read from this box (Ops confirms, step A3).

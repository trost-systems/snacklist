# Job 463: Mitteilungen as its own More item

**What changed for users.** More has a new row „Mitteilungen“ / "Notifications" below Einstellungen. It opens `/more/notifications` with the switch „Wenn jemand etwas hinzufügt“, the switch „Meinen Namen in Mitteilungen weglassen“, and the shopping-day weekdays. Einstellungen keeps theme, language, trip detection and shake. Every switch and chip there moves on tap. A failed save puts it back with „Die Änderung konnte nicht gespeichert werden.“, and refused notifications with the blocked notice. Today nobody sees any of this: the flags `push-household-add` and `push-shopping-day` are internal-only and push is held (`push-notifications`).

**Where.**
- `app/lib/more/notifications_page.dart`: the page and `notificationsShown`, the one rule for the row and the route.
- `app/lib/more/more_screen.dart`: `MorePage.notifications`, `_Item.notifications` in the settings group.
- `app/lib/shell/router.dart`: `notificationsPath`, its route (redirects to `/more` while nothing would show), screen name `notifications`.
- `app/lib/settings/settings_screen.dart`: no more `pushAlerts` and `shoppingDay` slots.
- `app/lib/push/household_add_settings.dart`: optimistic switches, queued taps, no section label.
- `app/lib/settings/shopping_day.dart`: queued picks, revert to what the server last took.
- Decisions: `docs/DECISIONS.md`, "Job 463".

**Tests.** `flutter analyze` is clean.
- `test/more/notifications_page_test.dart` (new, 10 tests): the row sits below Einstellungen in its group; it opens the page with both sections and back returns; Einstellungen has neither section with both flags on; one flag shows its section alone; three cases with no row whose link lands on `/more`; on wide screens the row is selected.
- `test/push/household_add_alert_test.dart`, 5 new tests: the switch moves before the server answers; a refused save puts it back with the notice; refused notifications put it back with the blocked notice; the name switch the same; quick taps are saved in order. 4 of them fail on the old widget (checked by restoring it).
- `test/settings/shopping_day_test.dart`, 3 new tests: a refused save puts the chip back with the notice; a pick during a save is kept and saved after it (fails on the old code); a refused pick before a saved one goes back to the server's days.
- Goldens `more-notifications-{light,dark}` and `more-notifications-row-{light,dark}` (`screens_golden_test.dart`). Existing More and Einstellungen goldens are unchanged, since they run with the flags off.
- On this box 8 goldens in `prices_golden_test.dart` and `screens_golden_test.dart` (list wide, add sheet wide, prices) fail the same way on an untouched `origin/main` checkout. That is environment, not this change. CI decides them.

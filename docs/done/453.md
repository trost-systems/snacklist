# Job 453: PostHog bug 1 (semantics `geometry!` TypeError)

**Status: bug 1 is not fixed in the app. Its cause is an upstream Flutter bug whose fix is in no stable or beta release yet.** It stays open in `docs/NEEDS_LEAD.md` ("Job 453"). This PR is docs only: it records the cause and fills in #711's merge commit in `docs/done/438.md`.

## Cause (upstream)

[flutter#195316](https://github.com/flutter/flutter/issues/195316), fixed on master by [flutter#192724](https://github.com/flutter/flutter/pull/192724) (merged 24 Nov 2026, commit `1c858ec5`). In `PipelineOwner.flushSemantics`, a semantics node whose geometry turned invisible adds its parent's nearest ancestor with clean geometry to the update targets. When the parent's geometry is dirty, the code reads the parent's `firstAncestorNodeWithCleanGeometry` cache without calling `computeAncestorInfo(treeShapeToken)` first. The cache can be left over from an earlier flush and point at a node whose geometry was cleared in this one. `ensureSemanticsNode()` on that node then throws in `_updateSemanticsNodeGeometry` (`geometry!`, our report) or `_buildSemanticsSubtree` (`geometry!.hidden`). It needs a branch kept out of the semantics tree (a dialog or sheet's `BlockSemantics`) while the page under it changes. The upstream reports name release builds from 3.44 to 3.47.x (3.47.0, 3.47.3 and 3.47.7 by number) with a screen reader or other accessibility service on, Android and iOS.

Job 438's lead (368a6dc1, deferred geometry for blocked branches) is not the cause. The faulty branch predates 3.50 (it came with flutter#184226). 3.47 builds were exposed too.

**Evidence.**
- The upstream regression test, "a node that becomes invisible while its branch is blocked does not crash when an ancestor geometry cache is stale" (`packages/flutter/test/widgets/semantics_blocked_geometry_test.dart` at `1c858ec5`, widgets library only; the same code is the sample in flutter#195316), run in `app/` against Flutter 3.50.0: fails with `_TypeError: Null check operator used on a null value`.
- The same test with `ExcludeSemantics`, `Offstage` or `IndexedStack` in place of `BlockSemantics`: all three fail on 3.50.0. The app hides a branch in each of these ways. The add sheet wraps the list in `ExcludeSemantics(excluding: open)` (`lib/list/list_screen.dart`), and go_router keeps inactive tabs `Offstage`. So the add sheet and tab switches are possible triggers, not only dialogs and bottom sheets.
- Neither 3.50.1 stable (20 Nov 2026) nor 3.51.0-0.2.pre beta has the fix: their `rendering/object.dart` lacks the `parentInSemanticsTree.computeAncestorInfo(treeShapeToken)` call.

## App repro attempts (none crashed)

The real list screen (`ShoppingList` with `FakeRepository`, semantics on, 16 ms frames), on stock 3.50.0 and on a copy of the SDK that logs every pass through the faulty branch:
- 390x844 and 1400x900, text scale 1.0 and 2.0.
- Blockers: the add sheet, the edit item sheet (long press), the list hidden the way go_router hides an inactive tab.
- Ops behind the blocker: remote add and add-many, delete, tick and untick, rename, category and store moves, quantity, offline and online (sync indicator), a random scroll position, a local tick. 8 rounds per run, 5 to 24 ops per round, 0 to 3 frames after each op.
- Seeds 1 to 60 with starting lists of 3 to 82 items, seeds 1 to 20 with 3 to 22 items, and 24 targeted "tick, then open the add sheet" cases. About 1,000 runs in all.

The app reaches the faulty branch: in 34 of 60 wide seeds, on the first frame after the add sheet opens with the list scrolled, the checklist card's `Semantics(container: true)` (`lib/tips/hint_views.dart`) read a stale cache. Every time the cache pointed at the root node, whose geometry is never cleared, so it could not throw. No run threw the null check.

## Why no app change ships

- No app-level trigger is proven, so a workaround (for example keeping the list's semantics and marking it hidden instead of `ExcludeSemantics` while the add sheet is open) would be a guess, and it would change what screen readers get. The brief rules out speculative patches.
- The fault is in framework code the app cannot patch. Every workflow installs Flutter by version (`FLUTTER_VERSION`); the store builds take theirs from `release.yml`.
- No stable Flutter carries the fix, so upgrading is not an option yet. The `RenderGlide` paint-shift mismatch from job 438 is unrelated; unchanged.

## Next step

Bump Flutter to the first stable that contains flutter#192724 (a 3.50.x hotfix if it is cherry-picked, else the next stable). The bump must change `FLUTTER_VERSION:` in every workflow that pins it (`grep -n 'FLUTTER_VERSION:' .github/workflows/*.yml`: `ci.yml`, `e2e.yml`, `release.yml`, `widgetbook.yml`, `store-screenshots.yml`, `add-sheet-timing.yml`, `paywall-shot.yml`). `release.yml` is the one that matters for users: it builds the TestFlight and Play binaries, and `scripts/check-gates.sh` keeps only `ci.yml` and `e2e.yml` in step, so bumping `ci.yml` alone would leave store builds on 3.50.0.

Check a release (a tag works in place of the hash):

```
curl -sf https://raw.githubusercontent.com/flutter/flutter/<tag>/packages/flutter/lib/src/rendering/object.dart -o /tmp/object.dart || echo 'fetch failed'
grep -c -e 'parentInSemanticsTree.computeAncestorInfo(treeShapeToken)' -e '^base class PipelineOwner' /tmp/object.dart
```

2 means fixed, 1 means not fixed (only the sanity line matched), anything else means the fetch or the file is wrong. Measured on 26 Nov 2026: 3.50.0 and 3.50.1 give 1, `1c858ec5` gives 2. The tests to rerun against a candidate SDK are kept in the job directory (`~/groceries-ops/jobs/453-posthog-semantics-geometry/probe/`: the upstream test, the three variants, the fuzz harness, and #192724's `object.dart` hunk as `fix.diff`); copy them into `app/test/` and run `flutter test` with the candidate SDK. They must pass.

Bug 1 can be closed only after a TestFlight or Play build from the bumped `release.yml` has shipped and PostHog shows no new reports from that build.

## Also found (not bug 1)

One fuzz case (1400x900, text 1.0, remote changes, then a programmatic jump to a random scroll position, no sheet open) fails Flutter's debug assertion `'!childSemantics.renderObject._needsLayout'` in `_collectChildMergeUpAndSiblingGroup`, then `'!semantics.parentDataDirty'`. These asserts are compiled out in release, and with them off the same runs throw no null check. Not tied to the reports; left as a note.

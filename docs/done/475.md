So the app-read holds are `native-siri` and `integration-lock`. They live in one place,
`APP_HOLDS` in `scripts/ci-changes.sh`. `scripts/ci-changes-test.sh` lists every file under
`app/`, `scripts/` (minus `scripts/release/` and `scripts/hold-flip-draft.sh` and its test), `e2e/`, `supabase/`, `alexa/` and `.github/` that
names flags.json (or `FLAGS_JSON`) and reads its holds (`.holds`, `holds[`, `"holds"`), takes the
quoted hold keys in those files, and fails unless that set equals `APP_HOLDS`. Today the scan
finds exactly the Fastfile and check.mjs.

## The rule

When `releases/flags.json` is in the diff, `site_holds_only` parses base and head with `node`
(preinstalled on the ubuntu-24.04 runner, and on hz and the Mac). The file drops out of the code
list, and `heavy` turns on as for a site file, when:

- both parse, and both have an object `holds`;
- everything but `holds` serialises identically (so any `flags` change, rollout or note, is code);
- the hold keys are the same set (a new or removed hold is code);
- no hold whose value changed (released or note) is in `APP_HOLDS`.

Anything else, or node missing, leaves the file as code (stack and app on). The other files in
the diff count by their own rules.

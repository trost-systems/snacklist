# Job 408: IKEA in the retailer registry

IKEA is a registry chain (`ikea`) with one entry per country where the official IKEA app is in the App Store
storefront: AT, BE, CH, CZ, DE, DK, ES, FI, FR, HR, HU, IE, IT, LU, NL, NO, PL, PT, RO, SE, SI, SK (22).
One app everywhere: "IKEA", Android `com.ingka.ikea.app`, iOS `1452164827` (bundle `com.ingka.ikea.app`, Inter IKEA
Systems B.V.). Not the separate IKEA Home smart apps.

Left out, with reason (the iTunes lookup returns no app in the storefront): BG, CY, EE, GR, IS, LV, LI, LT, MT.
Play shows anonymous clients one page for every country, so Android availability per country is not verified
(same limit as every entry).

- Checked on 2026-11-22: `scripts/retailers.ts --verify` (iOS lookup per storefront, Play title, AASA, asset
  links): 90 apps, 0 failed. `--check` is green.
- No universal link: www.ikea.com's AASA claims only paths templated per country and language, no plain home path.
  No scheme: no manifest evidence gathered.
- `aliases` is empty: matching folds case, so "IKEA", "Ikea" and "IKEA Hofheim" match through the name.
  Tests: `retailer_registry_test.dart`, `supabase/tests/retailers.test.sql`.
- `retailerChains`/`retailerCountries` in `events.dart` (the `store_app_opened` allow-list) list `ikea` and the
  new countries; `retailers.ts --check` requires it.
- Beyond the brief: `registryChains` and `registryRegion` skip IKEA, so the onboarding offers no IKEA chip and a
  phone in BE, CZ... still gets no chips. See the NEEDS_LEAD entry.

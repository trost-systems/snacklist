# Job 315: Rückgängig takes back the store and category picked after an add

**Bug.** Add „Quark“, pick Wochenmarkt and Getränke in the details under „✓ Hinzugefügt“, tap
„Rückgängig“: the item went, but the next Quark was offered at Wochenmarkt and stored under
Getränke. Every user had it since `add-feedback-list` went to full.

**Root cause.** Those picks reach the server as an update of the new item; `public.items_learn`
learned them without the undo marks `items_learn_insert` writes for a pick made with the add, so
`items_unlearn_delete` had nothing to take back.

**Fix.** Migration `20261119070000_undo_added_details.sql`: `items_learn` writes edit marks
(`edit_item`, `edit_by`, `edit_prev_at`, `edit_at`) on store and category changes, and a change to
„Ohne Laden“ keeps the store memory it deletes in `item_store_cleared.edit_stores`. The new RPC
`public.undo_add(p_item)` deletes the item and has `items_unlearn_delete` take those edits back.
The app's add sheet undoes through it (`DeleteItem(undoAdd: true)`). Every other delete keeps what
an edit taught, as the spec's classifier test wants (a first version that undid on any delete
within 10 minutes failed `classifier.spec.ts` and `voice.spec.ts` on CI). Without Rückgängig
nothing changes.

**Tests.** `supabase/tests/undo_added_details.test.sql` (27): no earlier lesson; an earlier lesson
with other values (counts and times restored); a pick of the remembered store and back; „Ohne
Laden“ and its orderings with a store pick; kept picks; a plain delete keeps the moves; a lesson
taught by another item after the picks survives; a tick in a store stays learned; another user's
`undo_add` does nothing, a retried one is no error; a store deleted after an „Ohne Laden“ pick does
not block the undo; „Ohne Laden“ picked with the add; a late (offline-queued) undo. With main's
trigger functions 12 of the first 24 fail. Two review subagents found four bugs between them, each
now a case. App: the add sheet's undo sends
`DeleteItem(undoAdd: true)` (`add_sheet_test.dart`), the repository calls `undo_add`
(`list_repository_test.dart`), the flag survives the cached queue (`list_cache_test.dart`).

**Verified in the web app** (verify-snacklist, `journeys/undo-added-details.mjs`): with main's
triggers the next Quark is „Quark, Wie getippt, Wochenmarkt“ and stored at Wochenmarkt / Getränke;
with the fix „Quark, Wie getippt“ and stored without a store under Kühlregal, as before the add.
With Quark taught at Supermarkt under Sonstiges first, the same steps end at Supermarkt / Sonstiges.
Screenshots in `docs/screenshots/315/`.

**Ships** with the next green main build to TestFlight and Play internal; no flag (the fix restores
the old chips' behaviour on the flag-on path). Older builds keep the plain delete, and the bug, until
they update.

## What was built (flag on)

- **The catalog on the phone.** `app/lib/list/catalog/catalog_index.g.dart` holds the dictionary's
  terms, the spelling forms and synonyms with their categories, the brands, and the parser's words
  (units, number words, descriptors). It is generated from the database by
  `supabase/classifier/client_catalog.sh`, and the db gate fails when it is out of date. It replaces
  `lexicon_forms.dart` and `number_words.dart`. Text only: no images, no user data.
- **Versioned, with daily changes.** `public.catalog_version()` names the catalog's rows.
  `public.catalog_delta(p_base, p_have)` gives a device the changes from the version it was built
  with. The device asks at most once a day while the flag is on, keeps the answer
  (`app/lib/list/catalog/catalog_loader.dart`) and lays it over the bundled catalog.
- **The household's side.** `public.suggest_index(p_household)` (members only) gives the device what
  the server's ranking reads of a household: its last year of items, one row per name, brand and
  details, its learned brands, and which DIY categories it lacks. Fetched on every resync and after
  deletes, saved with the list (`app/lib/list/catalog/household_index.dart`).
- **The server's ranking in Dart.** `app/lib/list/catalog/suggest_entries.dart` ports
  `suggest_entries` and `parse_item`; `pg.dart` ports pg_trgm's similarity, the edit distance and the
  database's sort order.
- **One table holds both.** `supabase/tests/suggest_parity.json` has 1,982 texts of a fixture
  household and the server's rows for each (5,943 rows). The db gate fails when the server's rows
  differ (`supabase/functions/_shared/suggest_parity_integration_test.ts`), the Flutter gate when
  the device's do (`app/test/list/suggest_parity_test.dart`). Today: 0 differences. Categories, from
  job 272's guess: 5,208 of 5,242 guessed rows agree, and the 34 others are listed by name.
- **The server only enriches.** Every key shows the device's rows for the text typed now
  (`add_sheet_cubit.dart`). The server's answer fills in category and store through job 272's
  `mergeRows` and never moves a row. Enter takes the first row at once. Offline the rows still come.

## How it was checked

- **Tests:** the parity table (both sides), `add_sheet_catalog_test.dart` (every key shows the
  ranking with the server held back; an answer in another order keeps the rows; a finger holds them;
  offline; Enter without waiting; the open-item note; a ranking that throws), loader, delta, index and
  fuzz tests, pgTAP `catalog_delta.test.sql` and `suggest_index.test.sql`. Mutants that drop the
  device ranking or its fallbacks fail them.
- **Driven on the web release build** (`.cursor/skills/verify-snacklist/journeys/on-device-catalog.mjs`,
  the server held back 2.5 s): after every key of "Hafer", "Erdbe", "Rote Be", "Pampers Windeln" and
  "2 l Hafermilch" the rows equal what the server answers for that text; the answer then changes
  nothing; a tap adds Erdbeere under Obst & Gemüse; offline the rows stay. Flag off, the control
  shows the old lag ("R, Wie getippt" for "Rote Be"). Screenshots in `docs/screenshots/274/`.
- **Timing** (DECISIONS "Job 274", point 7): web, the ranking at most 3.8 ms; Android emulator, UI
  thread per key p50 3.6 ms and p95 17.2 ms with the flag on (2.3 / 8.7 with `input-stable-rows`
  only), the ranking 0.6 / 2.9 ms. Not a phone: see below.
- **Review:** an independent review found a crash on a huge "Größe" number, deleted items staying
  offered until the next resync, a missed sign-in in the loader and a daily full catalog for some
  devices. All four are fixed with tests.

## Not done, or only partly

- **The 16 ms target on a phone is not proven.** No phone was measured. On the emulator the
  median key fits a frame easily, but p95 is just over 16 ms, and the second letter (one row becomes
  about eight) reaches 38.7 ms p95. With the other flags that same build lands in the server
  answer's frame instead. A profile build on a phone with `ADD_SHEET_TIMING=true` answers it
  (NEEDS_PETER "Job 274").
- A household brand learned since the last resync is not on the device yet: such a line is saved
  without the brand split off.
- The ranking copies the server's odd rows on purpose ("Rote Be" offers the brand "bebe"). A
  ranking change goes into the SQL and the port together; the parity table enforces it.

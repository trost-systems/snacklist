# Job 288: store and category in the add's details, the top bar away while the sheet is open

Flag: `add-feedback-list` (PostHog, live for all users; `releases/flags.json` now says `full`).
Peter's TestFlight feedback of 17 November on job 276. With the flag off nothing changes: every
existing golden passes without an update.

## What was built

- **No Store and Category chips at the top of the add sheet** with the flag on, in any state
  (`app/lib/list/add_sheet/add_sheet.dart`). The header keeps the grab handle and Schließen (✕),
  about 60 px tall instead of the chip row's 80. The sheet keeps one height (three rows) from the
  moment it opens, so nothing jumps when typing starts or an add lands.
- **Store and category moved into the added item's details**, in one line that scrolls sideways:
  Menge with − and +, the store chip, the category chip, Marke, Eigenschaften
  (`ItemDetailFields(inLine: true)` in `app/lib/list/edit_item_sheet.dart`, `FoldoutChips(line:)` in
  `app/lib/list/foldout_chips.dart`). A tapped chip folds its choices out below the whole line,
  scrolls them into view, and scrolls the line sideways to the opened chip. A pick saves at once
  (`AddSheetCubit.editDetails(now: true)`, the path the old chips took for the added item);
  „Neuer Laden“ works there too. No Done or Save button.
- **The list's top bar steps aside while the sheet is open**: the household or list switcher,
  „Anpassen“, the list tabs, the sync pill and the partner's new-adds capsule fade out over the
  existing 300 ms glide and fade back in as the sheet closes (reduced motion: at once). The rows behind
  the sheet take the room up to the status bar, which stays solid
  (`app/lib/list/list_view/shopping_list_view.dart` `_PinnedHeader`, `list_screen.dart`,
  `sync_indicator.dart`).

## A default store or category for the next add

The old chips set the store and category of the **next single add only**: `AddSheetCubit.take()`
started the picks over after every add („The picks start over with it“). No default ever lasted
longer than one item. The same result is now one step later: add the item, then tap its store or
category in the details line and pick. The pick is saved on that item at once, also as a new store
(„Neuer Laden“). The next item starts with Snacklist's own guess again, as before.

# Job 438: PostHog error-tracking reports (system back, semantics flush)

**Status: bug 2 (go_router `Bad state: No element`) is fixed at its cause. Bug 1 (semantics `TypeError`) remains open.** See `docs/NEEDS_LEAD.md`, "Job 438". Job 453 traced bug 1 to an upstream Flutter bug (flutter#195316); see `docs/done/453.md`.

## Bug 2: `Bad state: No element` in `_findCurrentNavigators`

**Cause.** A pop after a popup was closed during a save. The app opens dialogs and sheets on the root navigator (`popups-on-root-navigator`), whose only page is the tab shell. Many popups awaited a save and then called `Navigator.of(context).pop()` (or a navigator captured before the await), guarded by `mounted` at most. When the user closed the popup during the await (system back, Escape, a barrier tap, a drag), the popup stayed mounted for its exit animation but was no longer the current route, so the pop removed the shell page. go_router's configuration went empty; its `_debugAssertMatchListNotEmpty` is assert-only, so release builds show a blank app. The next system back (on Android the back gesture, the user's obvious move on a blank screen) reads `currentConfiguration.matches.last` in `GoRouterDelegate.popRoute` (go_router 18.1.1) and throws.

**Repro (review 2, release web build).** Mehr › Konto › „Dein Name“, type a name, Speichern with `POST /rest/v1/rpc/set_display_name` held, press Escape, release the request 40 or 80 ms later: the app goes blank (empty ARIA tree). Released after 1500 ms (sheet already disposed), the Konto page stays. On a phone network the save is slow, so the window is real.

**Fix.** `popIfCurrent(context, [result])` (`app/lib/core/pop_if_current.dart`) pops only while the context's own route is current (the pattern `list/store_details_screen.dart` already used). Every pop after an await that the rule below finds in `app/lib` goes through it, plus two it cannot see: the account name sheet, the name dialog (6 callers), the switcher's default picker and leave, archived households, the apps page's disconnect, the feedback sheet, the trip sheet's save and delete, account deletion; the annotator's close timer, and the trip summary page's `_leave` returns when its page is no longer current. The ast-grep rule `pop-if-current-after-await` reports `Navigator.of(...).pop`, `Navigator.pop(context)`, `context.pop()` and a captured navigator's `pop` in a function body that awaits, outside the helper (test in `ast-grep/tests/`). Its limits: it does not follow a pop in a helper, a Timer or a `.then`.

**Back on an empty configuration.** `SafeBackDispatcher` (`app/lib/shell/safe_back_dispatcher.dart`, wired by `guardedBack` in `app.dart`) stays as defence in depth for pops the lint cannot see: while the configuration is empty, back goes to the list (`router.go(listPath)`, answers handled) and reports `StateError('System back on an empty router configuration')` through `FlutterError.reportError`, which reaches error tracking like any framework error. So the user gets the list back instead of leaving a blank app, and a regression stays visible in PostHog. The allow-list scrubs the message, so search PostHog for `Bad state: <w> on an empty <w>` (checked with `scrubMessage`), distinct from go_router's `Bad state: No element`.

**Tests.**
- `test/core/pop_if_current_test.dart`, on the real widgets under a go_router shell like `buildRouter`'s: the account name sheet closed by system back during a held save, and the name dialog closed by a barrier tap during its save. Each expects the page under it to stay, a non-empty configuration and no error. Both fail without the fix (go_router's `currentConfiguration.isNotEmpty` assert; checked by restoring the old `account_screen.dart` and `name_dialog.dart`) and pass with it.
- `test/shell/safe_back_dispatcher_test.dart`: with a redirect held open (empty configuration), plain go_router reports `Bad state`; the guarded config answers handled, reports the `StateError` with its message and lands on the list. Root and in-shell back defer to go_router.
- `test/shell/system_back_test.dart`: back on the real `buildRouter` for signed out at `/`, the guided start step, a legacy `/settings` link and welcome reports no error and answers as expected. These pass with or without the dispatcher.

## Bug 1: `_updateSemanticsNodeGeometry` `geometry!` null check

Not reproduced, not fixed. The throw is inside Flutter's `_RenderObjectSemantics` (geometry cleared for relayout-boundary children, then read).

Audited: `_RenderMorph` (sync indicator), `MeasuredWidth`, `_RenderReportHeight`, `_RenderSnackBarsOnly`, `_RenderBackground`, the annotator's `_RenderFramed` (has `applyPaintTransform`) and `_RenderMeasuredHeight`, `RenderGlide`, and the list's `SliverMainAxisGroup` / `SliverCrossAxisGroup` with `SliverSemantics`. Finding: `RenderGlide` paints at `offset + paintShift` during list motions without reporting it in `applyPaintTransform`, so semantics rects ignore the shift while it runs. That is a mismatch, not shown to cause the null check, and I did not change it.

Smoke tests, not regression tests (they pass on main): `test/list/semantics_flush_test.dart` runs add sheet open, add, close and a scroll with semantics on, on a phone and in the wide column layout (glide and `SliverCrossAxisGroup` both run); the sync-indicator fold test in `sync_indicator_test.dart`. Also ran the list, shell, household, onboarding and more suites with semantics forced on for every test: no flush error.

**Flutter version.** CI and releases build with Flutter 3.50.0 since 13 Nov 2026 (#381); before that 3.47. Which build each crashing report came from is not visible from here, so "upgrade Flutter" is not the next step on its own.

**Leads (not causes).**
- Flutter 3.50.0 includes upstream commit 368a6dc1 "Defer semantics geometry updates for blocked branches" (flutter#192146): nodes that `BlockSemantics` blocks (the page behind a dialog or sheet barrier) go to a deferred set and are retried when the branch rejoins, in the phase that feeds `_updateSemanticsNodeGeometry` (`rendering/object.dart`, around 1449 and 1523-1542). The reports start on 3.50 builds. Seven probes (relayout, grow and shrink, AnimatedSize, AnimatedSwitcher, adding and removing nodes behind a dialog or sheet closing mid-animation) did not reproduce it.
- Bug 2's path tears down the whole shell subtree while a root popup animates out, the same blocked-branch situation. Probed with `ensureSemantics()` on the old name sheet and name dialog (shell popped mid-exit): no geometry error, but in a debug test go_router's assert stops the pop first, so the release path is not covered. If bug 1's reports stop on builds with `popIfCurrent`, this was likely it.
- To try: the app's real sheets and dialogs with the list changing behind them (a realtime update, the sync indicator folding while the add sheet or a dialog is open); check the Flutter tracker for a geometry-null report against 3.50. Next steps: the stack's app build and platform (web or native) from the four testers' sessions.

No `supabase/functions`, ARB or legal file touched. Merged as PR #711, merge commit `630e77a7a` (`630e77a7ade8a868288c90d5a89656b4d63d6768`).

**Review 3: switcher leave.** Converting `switcher_household.dart` to `popIfCurrent(context)` broke closing the switcher after a leave when the reload after it is slow: `SessionCubit.leave` emits the state without the household before its reload, the sheet's `AnimatedSwitcher` fades `SwitcherHousehold` out, and its context is unmounted when `leave` returns, so nothing popped (the sheet stayed open). Now it captures the sheet's route before the await and pops it with `popRouteIfCurrent(route)` (`core/pop_if_current.dart`). New test in `switcher_sheet_test.dart`, with `TestSession.leave` awaiting after it emits: fails with the round-3 call site, passes with the fix. Audit of the other converted sites (each must pop from a context of the popup route itself, not a subtree that can go while the route stays): name dialog, account name sheet, delete-account dialog, access details sheet, default picker, archived households, feedback sheet, trip sheet and annotator each pop from their route's root state; only the switcher's inner page was affected.

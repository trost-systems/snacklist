# Job 479: the name switch no longer waits for `push-household-add` (N-425)

Legal review 2026-11-26-snacklist-710, N-425. The Art. 21 switch „Meinen Namen in Mitteilungen weglassen“ (`pushNameHidden`) showed only while the PostHog flag `push-household-add` was on. A stepwise rollout of that flag would let members who already have it name a member who does not, and that member could not object. After this job the name switch shows in every build with the flag off too. Only the alert's own switch still waits for the flag.

## Decisions

Moved from `docs/DECISIONS.md` (job 479d), where its headings were the two below one level up. The numbering is kept.

### Job 479 (N-425: the name switch without `push-household-add`), 2026-11-26

1. **Mitteilungen is listed for everyone.** The name switch is the page's only always-present section, so More shows the Mitteilungen row and opens `/more/notifications` in every build, with every flag off too, the web included. Hiding the row while the page holds only the name switch would bring back the gate N-425 removes. Changing it touches `notificationsShown` in `app/lib/more/notifications_page.dart`.
2. **The switch shows before any push is sent.** While `app_switches.push_household_add` is off, no push names anyone, so the switch has nothing to act on yet. It is shown anyway: the objection should be on record before the first push, not after. No new copy explains this. The existing hint already says what the switch does.
3. **`releases/flags.json` notes stay stale.** The `push-household-add` and `push-notifications` notes still say the switch is gated on the flag. The brief forbids a flags.json change, so updating them is left to a follow-up after Legal's GO (docs/done/479.md).

### Job 479b (review 2 of #759: a spinner while the name switch loads), 2026-11-27

1. **The spinner shows only while a read runs.** Mitteilungen's household-add group shows a 20 px spinner while `refresh` runs and no choice is known, the failure line after a failed read, and the switches once read. When the alert forgets the choice for a new account while the page stays open, no read runs and the group stays empty, as before: that page is left on sign-out, so the state is not reachable in the app, and a spinner there would turn forever.
2. **During a retry the failure line stays with a disabled button.** Swapping it for the spinner would make the line flicker away and back on a second failure; a disabled button says a try is under way without new text.
3. **The spinner's screen-reader label is the existing `loading` key** („Lädt …“ / "Loading…"). An unlabelled spinner has no semantics node on the web, so a screen reader would find an empty page. No new string goes to Legal.

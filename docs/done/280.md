## What was built

- `scripts/waitlist/ios-invite.ts`: mails the beta invite to confirmed iPhone sign-ups, one Resend
  single send each, in the sign-up locale, from `"Peter · Snacklist" <hello@snacklist.app>`. The
  dry run is the default. It prints counts and writes redacted previews (DE and EN, text and HTML,
  with the real headers). A send needs `INVITE_SEND=1`, `BATCH_SIZE` and `INVITE_CONFIRM` (the dry
  run's token over the batch and the mail). Each row is claimed before its send and released only
  on a 4xx refusal (not 408 or 409), so no rerun mails anyone twice; no answer or a 5xx stops the
  run with the row kept.
- Migration `20261116120000_waitlist_ios_invite.sql`: `waitlist_ios_invite_counts`, `_rows`,
  `waitlist_invite_claim`, `waitlist_invite_release` (service role only).
- `mail.ts`: the iOS invite's footer is Legal's N-261 (batch of 2026-11-17) word for word, DE and
  EN, with the signed unsubscribe page as its link. Review 2 replaced the earlier
  `⟦FOOTER: Legal Q17⟧` slot. The From header is unchanged (N-262 not applied).
- `invite.ts` leaves iOS rows alone (Android only).
- `scripts/waitlist/ios-invite-proof.ts`: the local end-to-end proof.
- Docs: `docs/WAITLIST.md` "iOS invite", DECISIONS "Job 280", FEATURES-FOR-WRITERS waitlist section.

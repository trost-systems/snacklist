# Job 464: switches and pickers change at once

Peter (26 Nov 2026): the "when someone adds something" switch waited for the
server before it moved. The app should feel quick. A control without its own
loading state changes at once and goes back, with a snackbar, if the save
fails.

## Rules (AGENTS.md, Conventions)

- Optimistic UI: a control without a loading state shows the change at once,
  calls the server, and on failure restores the old value with a snackbar.
  A widget test covers both.
- App links: the app's paths on `app.snacklist.app` and `snacklist.app` open
  the installed app; `appLinks`, AASA, `assetlinks.json`, the Android
  `autoVerify` filter, the entitlements and the router change together;
  browser-only paths are never claimed. Job 462 implements the links and
  `docs/DEEP_LINKS.md`.

`CLAUDE.md` is a symlink to `AGENTS.md`, so it needs no pointer.

## Tests

- `test/household/default_list_test.dart` "the pick shows before the server
  answers; a refusal puts it back and says why".
- `test/household/switcher_test.dart` "the default picker checks the tap at
  once; a refusal puts the check back and says why".
- `test/household/default_list_test.dart` "two picks that both fail put back
  the saved one": the menu reverts to the pick the server last confirmed, not
  to an earlier pick still saving (review 1).
- `test/household/default_list_test.dart` "an older pick that saves after a
  newer one failed shows": once no pick is still saving, the row shows the
  last confirmed pick (review 2).

The app-links bullet is the rule Peter set (t1312u) for every host and path
the app should take. Today only `app.snacklist.app` and `app.hummlist.com`
are claimed; job 462 adds the rest and updates `docs/DEEP_LINKS.md`.

Both hold the server's answer open (`TestSession.hold`), check the new value
before it comes, then fail it and check the old value and the offline
snackbar. Both fail on the old code (the new value is missing while the
server waits) and pass on the new.

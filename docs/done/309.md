# Job 309: fewer CI jobs, gates by what a PR touches, an e2e budget (OC2, OC5, OC3b, OC3c, 2026-11-18)

CI, workflows, scripts and e2e tests only, no app code. PR #544. Decisions: `docs/DECISIONS.md`,
job 309. How it works: `docs/CI.md`, sections "Jobs and gates", "Which gates a PR runs" and "The
e2e budget".

## What changed

- **OC2, fewer jobs.** `ci.yml` packs the small gates into three jobs:
  - `lint` runs gitleaks, changelog (pull requests only, not Dependabot) and lint.
  - `deno` runs functions, nexus and fg-cli.
  - `site` runs site and site-agent.

  Each gate stays its own script and its own step. A gate after the first runs `if: ${{
  !cancelled() ... }}`, so one red gate still lets the next report. `scripts/check-gates.sh`
  requires exactly one job to run each gate script, once, with that job in `ci-ok`'s `needs`, and
  the `if:` on every later gate. `verify.sh` and its gate names are unchanged. `main` has no
  branch protection or ruleset, and `merge-pr.sh` waits for `ci-ok` only, so there were no other
  required checks to update.
- **OC5, gates by what a PR touches.** `scripts/ci-changes.sh` adds two outputs, `stack` and `app`.
  - `stack` runs db and e2e. It is off when every changed file is documentation, `site/`,
    `nexus/`, `marketing/`, `research/`, `mcp-proxy/`, `tool/hotspots/` or `tool/hillclimb/`.
  - `app` runs flutter and web-prod. It is also off when the rest is `supabase/`, `alexa/` or
    `e2e/`.
  - Any other path turns both on.
  - The files outside `app/` that the Flutter tests read keep `app` on. `scripts/ci-changes-test.sh`
    finds them itself (every `'../...'` literal in the Flutter tests) and fails when one does not
    turn `app` on.
  - DB-only PRs keep e2e. This departs from the brief, for the reason in DECISIONS, item 4.
- **OC3b, e2e budget.** `e2e/budget.mjs` runs in the lint gate. It lists the suite as CI runs it
  and prices each test from `e2e/shard-durations.json`. It fails above `e2e/budget.json` (300
  tests, 3,800 s) and warns from 98 %. Listing needs no stack, because `e2e/tests/iap.ts` now
  reads `supabase/functions/.env` only when a RevenueCat event is sent.
- **OC3c, duplicate audit.** See the table below.
- `scripts/ci-queue.sh` measures how long PR runs' e2e shards waited for a runner, and how many
  jobs each run started.

## OC3c: e2e tests removed, with reasons

A read-only pass compared every spec, pgTAP test and Deno test, and I checked each candidate
against its replacement's assertions. Two of the 290 tests are clear duplicates and are removed.

| Removed test | Duration | Covered by | Reason |
| --- | --- | --- | --- |
| `social-sign-in.spec.ts` "password sign-in still works next to the providers" | 10.7 s | `auth.spec.ts` "email and password: sign out and back in" | Both sign up with a household, sign out through More › Abmelden and sign in with the same password on the same login screen, which always shows the providers. Both end with the add field focused. The auth test also checks a wrong password and that no credentials stay in the page. The removed test asserted nothing about the provider buttons. |
| `households.spec.ts` "an old app's own-membership read stays one row for a user in three households" | 0.5 s | `supabase/tests/households_multi.test.sql` (old `create_household`, a second one with a request id, `accept_invite` mode add, "the old app's own-membership query returns exactly one row, the default") | The test was API-only and made the same calls and checks as the pgTAP test, through the same RLS. The PostgREST `.maybeSingle()` read is still exercised by `households.spec.ts` "the default for Siri, Alexa and AI changes from the switcher". |

Kept, though proposed: `live-sync.spec.ts` "an invite link takes a new user through sign-up
straight into the household". Its parts are tested elsewhere: the link join in `invite-loop.spec.ts`,
and live sync after a typed-code join in `live-sync.spec.ts`. No single test covers link join
followed by live sync, so it is not a clear duplicate. The audit rejected 21 more near-duplicate
pairs because each asserts something of its own. Examples: the burst rate limit through the real
gateway (`public-api.spec.ts`) against the Deno unit test, real GoTrue tokens (`mcp.spec.ts`)
against synthetic JWTs, and WebKit against Chromium runs.

## Checks run

- `scripts/verify.sh --only gitleaks,lint,changelog,fg-cli,nexus,functions`: passed. The lint gate
  includes `check-gates.sh`, `ci-changes-test.sh` and the budget.
- check-gates mutations each fail with a message naming the fix: a later gate without `!cancelled()`,
  a gate run twice, `deno` missing from `ci-ok`, and site-agent run by no job.
- ci-changes-test with the list of files the Flutter tests read emptied: 17 failures, 13 of them from
  the derived loop.
- CI run 44341731952 on the first commit: all 17 jobs green, iOS and ios-storekit included.
- In-session review (read-only, separate agent): no must-fix. Its nice-to-haves are fixed and each
  fails on the mutation the reviewer used. db, e2e or deno moved to another switch now fails
  `ci-changes-test.sh`. A second gate in the e2e matrix job, or a `continue-on-error`, fails
  `check-gates.sh`. A non-ASCII `app/ios/` name failed the native rule without `core.quotePath=false`.
  `node e2e/budget.mjs` from a checkout path with a space and "perf" in it prints 288 tests; before,
  it printed nothing (main-module check) or 291 (the `@perf` tests).

## Not done here

- **OC1 interplay.** On a main push that reuses its PR's run, job 308's `reuse` turns every switch
  off. The lint job, which now holds gitleaks, skips with it. The tree is the PR head's, which the
  PR run already scanned.

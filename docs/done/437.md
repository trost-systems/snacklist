## mcp.spec.ts: #312, #395, #68, #69, #70

- All five failed the same way: a 60 s test timeout (or a 15-20 s predicate) with no named request.
  #68, #69 and #70 are the local runs during the box VM pauses of 2026-10-25..28 (`[host-stall]`
  lines, passed on the stall retry). #312 and #395 (2026-11-07, 2026-11-13) hung on the first
  unauthenticated request of the Node-side `StreamableHTTPClientTransport`.
- Root cause of #312 and #395: the edge runtime drops an early answer to a POST whose body is
  unread, so the client got no byte (memory "Edge runtime drops early answers"). #440 (2026-11-14)
  makes the functions answer only after the body arrived, and gives every Node-side request a
  15 s deadline (`e2e/tests/deadline.ts`) and one retry of an empty 502/503/504/546
  (`timedFetch`, `e2e/tests/mcp-helpers.ts`). A hang now fails fast naming the request.
- Since #440: no `mcp.spec.ts` failure in the main and PR CI runs from 2026-11-23 on (the 200
  newest CI runs; 6 failed, none in mcp or live-sync: `integration-lock.spec.ts:94`,
  `stores-add.spec.ts:81`, and four Flutter, deno, db or iOS-image failures).

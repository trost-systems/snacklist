# Job 462: app-routable links open the installed app

PR: https://github.com/trost-systems/snacklist/pull/731. Decisions: `docs/DECISIONS.md`, "Job 462". Runbook: `docs/DEEP_LINKS.md`.

## Diagnosis (26 Nov 2026, from Hetzner; the box's IP is challenged by Vercel)

- **App host.** `app.snacklist.app/.well-known/apple-app-site-association` is 200 `application/json`, and Apple's CDN has the same file. `AASA-Bot/1.0.0` gets a 200. `http://` gives a 308 to https. The 500 came from the box's proxy.
- **Root path.** `app.snacklist.app/apple-app-site-association` was the SPA (text/html). It is JSON now.
- **Site.** `snacklist.app/.well-known/*` returned 404, and Apple's CDN and Google's statements API had no entry. `www.snacklist.app` redirects with a 308, so it is not claimed.
- **Fingerprints.** Google lists the app host's three fingerprints, and they match `docs/RELEASE.md`.
- **Likely cause.** The entitlement and AASA were right for `/join/*`. The likely cause is a URL typed or pasted into Safari, which never fires a universal link. The new "In der App öffnen" covers that case.

## Built

- **Link table.** `app/lib/core/deep_links.dart` holds `appLinks` with `LinkHost.app` and `LinkHost.site`. The AASA of both hosts, two Android verified filters and the entitlements follow it. `deep_links_config_test.dart` checks all of them.
- **Router.** The guide routes are public. The new app-host paths continue after sign-in, except `/households/new`. Router tests cover the `com.snacklist.app://open/join/<code>` hand-off and the unchanged `login-callback`.
- **Guide view.** `app/lib/guides/` holds a typed model, a fetch and the native page.
- **Guide JSON.** `site/guide-data.mjs` writes it from the site's gated tokens, so it shows what the HTML page shows.
- **Hand-off.** `app/web/join/join.js` and `site/public/open-in-app.js`.

## Never claimed

- **App host:** `/`, `/login`, `/welcome*`, `/start*`, `/your-name`, `/analytics-consent`, `/oauth/consent`, `/settings`, static files.
- **snacklist.app:** everything but the guides. That covers the landing pages, legal and support, changelog, comparisons, waitlist, `/data`, `/api` and llms.txt.
- **www.snacklist.app:** not claimed, because it redirects.

- the guides on snacklist.app

Without a new build:

- **Join page's "In der App öffnen".** It goes live with the next `release` push. On iOS it should also work with 1541, which already has the scheme and the route. This is inferred, not tested on a device.
- **Site files.** They go live with the site's production deploy after merge.

# Job 462: app-routable links open the installed app

Peter (t1309u, t1312u, 26 Nov 2026): `https://app.snacklist.app/join/<code>` opened Safari on his
iPhone (TestFlight 1541, app closed); every app-routable link on snacklist.app and
app.snacklist.app should open the installed app, and stay in the browser without it.

Merged as: the next commit on main (PR head in the PR).

## Diagnosis (26 Nov 2026, about 10:15 to 10:30 Europe/Berlin)

- `https://app.snacklist.app/.well-known/apple-app-site-association`: 200, `application/json`,
  no redirect, `/join/*` and the other paths for `VCZSHMZY25.com.snacklist.app` and
  `.com.hummlist.app`. Apple's CDN (`app-site-association.cdn-apple.com/a/v1/app.snacklist.app`):
  the same file, fetched fresh (`Age: 0`). app.hummlist.com: the same.
- `https://app.snacklist.app/apple-app-site-association`: 200 `text/html` (the SPA). Fixed here.
- `http://app.snacklist.app/.well-known/apple-app-site-association`: 308 to https now (the 500 the
  brief saw is gone).
- `https://snacklist.app/.well-known/*`: 404; Apple's CDN `SWCERR00101`. Fixed here (site files).
- `https://www.snacklist.app/...`: 308 to snacklist.app, so www is not claimed.
- Build 1541 is release.yml run 531 (commit c8c1cd077, uploaded 2026-11-24 22:37 UTC). Its
  `Runner.entitlements` has `applinks:app.snacklist.app`; the build signs manually with "match
  AppStore com.snacklist.app", which fails when the profile lacks the capability. No log line
  prints the signed entitlements, so this is indirect.
- Conclusion: the app side and the domain file were in place. Universal links do not fire for an
  address typed or pasted into Safari, a tap on a page of the same domain, or once "open in
  Safari" was chosen; that is the likely case. Not reproducible without an iPhone.

## What changed

- **Route tables** (`app/lib/core/deep_links.dart`): `appLinks` adds `/history`, `/history/*`,
  `/edit`, `/edit/*`, `/trip/*`; new `siteLinks` (snacklist.app) `/de/anleitungen`,
  `/de/anleitungen/*`, `/en/guides`, `/en/guides/*`; hosts as constants.
- **Router**: guide routes for every session (no sign-in, no consent first); `/edit`, `/history`
  and trip links survive sign-in as `next`; screen name `guide`.
- **Guide view** (`app/lib/guides/`): reads the site's Markdown twin (`<page>.md`), renders it
  natively with `package:markdown` (headings, lists, quotes, code, tables as one card per row);
  links to guides stay in the app, links to app paths go there, others open the system browser;
  missing and failed states. On the web it goes to the site.
- **iOS**: `applinks:snacklist.app`. **Android**: a second verified filter for snacklist.app and
  the guide paths; the first gets the new app paths.
- **Hosting**: app AASA with the new paths; site `.well-known/apple-app-site-association`
  (`com.snacklist.app`) and `assetlinks.json` (the app's com.snacklist.app statement, same
  fingerprints); `/apple-app-site-association` served as JSON on both projects.
- **Browser handoff**: „In der App öffnen“ on phones on the join page and the site's guide pages and
  lists (iPhone: `com.snacklist.app://open<path>`; Android: `intent://` with the page as fallback).
- **Checks**: `deep_links_config_test.dart` (entitlements, both AASA files, both filters, both
  assetlinks, both vercel.json), router and trip route tests, guide tests (42, live twins as
  fixtures), `e2e/tests/join-page.spec.ts` (5 new), `site/test/open-app.test.mjs`,
  `e2e/web-smoke.mjs` (stale `/join` expectation fixed, `/apple-app-site-association` checked).
- **Docs**: `docs/DEEP_LINKS.md`, DECISIONS "Job 462", NEEDS_PETER "Job 462", the app-links
  feature file and FEATURES-FOR-WRITERS.

## Store build

- `/join/<code>` (Peter's link): **no new build needed.** 1541 has the entitlement and registers the
  `com.snacklist.app` scheme; the join page's button goes live when app.snacklist.app moves, that is
  with the next store upload (`release` branch, every green main commit through `release.yml`).
- Guides on snacklist.app, the new app paths' claims, the guide view, Android's new filter:
  **a new TestFlight / Play build is required.** The site's association files go live with the
  merge (the site deploys from main).

# Job 328: Premium gate for export, API and MCP (off during the beta)

PR: https://github.com/trost-systems/snacklist/pull/577. Merged as: the next commit on main.

**What users get today.** Nothing changes. The switch is off, so the API, MCP and the data
export stay open for everyone during the beta (PX1).

**What is built.**
- **Server (already there since job 50, now tested for all three states).** While
  `app_switches.integration_lock` is on, `public.integration_gate` refuses a caller without
  Premium. Premium means the household's plan (job 49) or the caller's own (job 185, #387), read in
  Postgres, never from the app. The API answers `402 premium_required` ("This household needs
  Snacklist Premium to use the API. Unlock it in the Snacklist app. Nothing was read or changed.",
  docs/API.md, docs/api/openapi.yaml). MCP tool calls get a tool result with `isError: true` and
  the German or English sentence (docs/MCP.md). Tokens, keys and links are never revoked or
  changed.
- **App: the new remote switch `premium-gate-integrations`** (PostHog flag, off). It replaces the
  build define `INTEGRATION_LOCK`, so turning the lock on needs no new store build. With the flag
  and the server switch on, a user without Premium sees in Mehr › Zugänge the card „Teil von
  Snacklist Premium“, their connections as „Pausiert: braucht Snacklist Premium“, and „Snacklist
  Premium freischalten“, which opens the Premium page (on the web: buy it in the app).
- **Export.** „Meine Daten exportieren“ is the GDPR copy of the account and stays free by law.
  Nothing else exports today; Premium's "export" is the API and MCP (DECISIONS "Job 328", 3).

**Tests.**
- `supabase/functions/api/api_integration_test.ts`: switch off 200; switch on, no Premium 402 with
  its message; switch on, the key holder's own yearly plan 200 (new). With
  `_shared/premium_integration_test.ts` (MCP, all three states): 19 passed on the local stack.
- `app/test/settings/integration_lock_test.dart`, group `premium-gate-integrations`: flag off shows
  nothing with the server switch on; flag on with Premium is open; flag on without Premium shows
  the card, pauses the token, and its button opens the Premium page. 452 passed in test/settings,
  test/more, test/purchases. Removing the flag check fails the flag-off case.
- e2e `tests/integration-lock.spec.ts` (flag forced in the e2e build): 3 passed.
- Driven on the web release build (port block 538), screenshots in `docs/screenshots/328/`:
  switch off (no card, API 200, MCP ok), switch on and Free (card, paused, API 402, MCP refused),
  switch on with Mia's own yearly plan (no card, API 200, MCP ok). `03-app-locked-buy.png` is the
  phone app's card with its Buy button (the widget screenshot test with the fake store).

**Turning it on (Peter's go, docs/PURCHASES.md "Go-live order").** Server switch
`integration_lock` first, then the PostHog flag `premium-gate-integrations` (Peter's install first
for TestFlight, then everyone). The next green main build carries the app side; with the flag off
it looks as before.

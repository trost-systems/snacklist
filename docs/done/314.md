## Data model proposal

- **Registry.** `retailers.json` is the source, reviewed in PRs. It is keyed by chain and country (ISO 3166-1 alpha-2) and holds the name, the aliases, and the app: its name, Android package, iOS id, the https link that opens it (only where the AASA claims it), and the store fallbacks. Each entry also has a status, a verified date and its sources.
- **Where it lives.** The deploy loads it, with an idempotent upsert, into `public.retailers`. That table is public data: RLS on, select for anon and authenticated, no `household_id`. The app reads it once a day, caches it in `DeviceCache`, and bundles a snapshot for an offline first start. MCP and Siri read the same table. PostHog flags (`open-store-app`) only switch the feature, per country if needed; they hold no data.
- **Stores.** Three nullable columns: `retailer_chain`, `retailer_country` and `branch`. A foreign key to `retailers` uses `on delete set null`. The user's own name stays the label. Today's `seed_key` values dm, lidl and edeka become `dm:DE`, `lidl:DE` and `edeka:DE`.
- **Matching.** `public.match_retailer(household, name, country)` runs server-side next to `classify_item` and shares `store_name_key`, so the app, MCP and Siri agree.
- **Adding a country.**
  1. Add its entries to `retailers.json`.
  2. Run `node registry/verify-registry.mjs --only <CC>`, which checks Apple, Play, the AASA files and Digital Asset Links.
  3. Open a PR. The lint gate runs the offline schema check.
  4. Merge. The deploy upserts the rows, and the app has them within a day.

  No app release is needed. Android uses `startActivity` and catches `ActivityNotFoundException`, with no `<queries>` (SS-Q5, to be confirmed on a device). iOS uses https and `itms-apps://` links.
- **Today's registry.** It has 58 verified entries: DE 10, AT 7, CH 5, FR 8, NL 7, PL 7 plus Dino with no app, IT 7, ES 7. 21 of them have a verified link that opens the app. Nothing is TODO. The open items are Android country availability (Play shows the same page in every country), the choice between two apps for a few chains, and a device test of the 21 links. All of these are in `registry/REGISTRY.md`.

## Privacy

No option needs location by default. Only SS3 uses it, once per tap, and it sends the location to a map service. Google Places is paid, and OSM's public Nominatim doesn't allow app-scale use, so SS3 would need a processor contract (a note for Legal). Store names stay in the household, and matching runs on our server against public data.

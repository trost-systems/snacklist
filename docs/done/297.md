# Job 297: the name after sign-in (DN3) and Konto › Dein Name (DE1)

Peter picked DN3 and DE1 from the job 293 prototypes. Everything ships behind the new PostHog flag
`display-name` (`releases/flags.json`, rollout off). With the flag off the app is unchanged.

## What users get with the flag on

- **The name step, `/your-name`.** It comes right after sign-in and the usage-data question.
  - The heading is „Wie sollen wir dich nennen?“ / "What should we call you?".
  - A Google or Apple name is prefilled, and „Ja, das bin ich“ saves it in one tap.
  - Without one the field is empty and required, from 1 to 80 characters. Emoji are allowed, and spaces are trimmed and collapsed.
  - Creators see it before the household setup. Joiners see it before the join screen, and the invite rides along.
- **Members whose name is still the e-mail prefix** are asked once per device, with „Jetzt nicht“.
- **Mehr › Konto › „Dein Name“** is the first row. It shows the name, or „Namen eintragen“ when there is none.
  - The row opens a sheet. Save is off while the field is empty or unchanged.
  - Saving shows „Name gespeichert“.
  - There is one name for all households.
- **A chosen name is never replaced by a later Google or Apple name.**

## Where

- **Server.** `supabase/migrations/20261117211652_display_name_chosen.sql` holds the migration:
  - `profiles.display_name_chosen_at`.
  - `set_display_name(p_name)` normalizes, validates and stamps the name. It is now the only writer: the unused column grant is revoked.
  - `my_display_name()` returns `display_name`, `chosen` and `from_email`.
  - The metadata trigger now skips chosen names.
- **Server tests.** `supabase/tests/display_name_chosen.test.sql` has 17 cases. Put back the old trigger body and two of them fail.
- **App.**
  - `app/lib/session/your_name.dart` holds the state, the cubit, the repository and the `asksName` rule.
  - `app/lib/session/your_name_screen.dart` is the step.
  - `app/lib/settings/account_screen.dart` has the row and the sheet.
  - `app/lib/app/router.dart` puts the gate in `authRedirect`, after the analytics consent.
  - `app/lib/app/device_cache.dart` stores „Jetzt nicht“.
  - `app/lib/analytics/flags.dart` defines `displayNameFlag`.
  - The copy is in `app/l10n/app_{de,en}.arb`.
- **App tests.**
  - `app/test/session/your_name_test.dart` covers the normalizing, the `asksName` table and the cubit.
  - `your_name_screen_test.dart` covers DN3: the prefilled name saves in one tap, an empty field is required, „Jetzt nicht“ shows only for members, Apple's late name arrives, and 200 % text in light and dark.
  - `your_name_gate_test.dart` runs the real router with the flag off, on, and served late.
  - `app/test/settings/account_name_test.dart` covers DE1: save and validation, flag off, 200 % in light and dark.
  - New cases in `app/test/app/router_test.dart`.
- **Verify skill.** `.cursor/skills/verify-snacklist/features/display-name.md`, `journeys/display-name.mjs` and a section in `FEATURES-FOR-WRITERS.md`.
- **Decisions.** `docs/DECISIONS.md`, section "Job 297".

## Not done or blocked

- The real Google and Apple sheets can't be driven here. A sign-up with `full_name` metadata stands in, since the profile trigger reads it the same way.
- The iOS and Android apps were not driven, only the web build.
- Turn the flag on only after `supabase-deploy` has deployed the migration. Without `my_display_name` a new user would sit at the retry.

## Review 0 fixes (2026-11-18)

- **Sign-out on the name step.** „Abmelden“ is now in its app bar, so a wrong account isn't stuck. It lands on the sign-in, and no name is saved.
- **One length count.** The field refuses an edit past 80 code points, as the server counts them.
- **Invisible names refused.** The app and `set_display_name` both refuse a name made only of zero-width characters.
- **Konto after a failed read.** The row stays, with a retry.
- **Left as is.** A member can still meet the step mid-session; DECISIONS item 17 explains why.
- **Tests.** pgTAP is now 19 cases. New widget tests cover sign-out (screen and router, with and without an invite), the code-point limit, zero-width names and the Konto retry. The journey's new wrong-account walk passed in DE light and EN dark.

## Matching
Case-insensitive through name and aliases: "Hornbach", "OBI", "Toom", "Bauhaus", "Hellweg", "Hagebau",
"hagebaumarkt", "Globus Baumarkt", "Globus Bau" each match their chain.

Ambiguous names (lead update, Peter t1204u, 2026-11-23 07:53, missed in the first land and fixed in review 0): plain
"Globus" is both the grocery Globus (Mein Globus) and Globus Baumarkt, because the Baumarkt carries the alias `globus`.
Both match exactly with equal key length, so the existing "which chain?" question asks (`Welches Globus?`: buttons
„Globus“ and „Globus Baumarkt“, plus „Keins davon“), in the store create flow, the add sheet's suggestions, the chain
picker and the list card, and the answer is stored on the store (`answer_store_retailer`). An explicit "Globus
Baumarkt" or "Globus Bau" has the longer key and matches the DIY chain alone. The buttons differ by name, so no new
copy was needed. `retailers_test.ts` checks the whole registry: the only names shared by two chains in one country
are Aldi (DE) and Globus (DE). Adding another is a deliberate edit of that list. No collision elsewhere.

Existing stores named "Globus": the lead asked that they keep their current grocery match. None had one, because the
registry held no grocery Globus. They are now asked once on the list ("Ist dein „Globus“ die Kette ..."), with a plain
Nein; nothing is linked without that answer, so nothing changes silently.

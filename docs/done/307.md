# Job 307: CI quick wins OC3a and OC4 (2026-11-18)

PR #545. Brief: `in/openclaw-ci-fit.md` items OC3a (the `mcp.spec.ts:27` flake) and OC4 (checks
before the push, and the cancelled PR runs). Decisions with their evidence: `docs/DECISIONS.md`,
"Job 307".

## What changed

- **`scripts/push-checks.sh`** (new) runs the quick checks of the lint and flutter gates for what
  the branch changes against `origin/main`. `scripts/lint.sh` runs on every push. The others run
  by changed path: `actionlint`, `shellcheck` on the changed scripts, the TypeScript pack
  (`tool/lint/ts/strict.ts`), the e2e `tsc`, and `scripts/gates/flutter.sh --no-tests` (lockfiles,
  l10n, format and analyze for the app and the Widgetbook). It runs every check that applies and
  then names the failed ones. `--list` prints the checks without running them.
- **`scripts/push-pr.sh`** runs it before every push and pushes nothing when a check fails. The
  message names the failed checks. `PUSH_PR_SKIP_CHECKS=1` skips the checks, for a machine that
  can't run one.
- **The flutter gate** gained `--no-tests`, and its l10n and format failures now say which
  command fixes them. **The lint gate** reads its shellcheck file list from `shell_scripts` in
  `lib.sh`, which push-checks uses too.
- **Draft PRs run no CI on open.** In `ci.yml`, `changes`, gitleaks, changelog and `ci-ok`
  skip on an `opened` event of a draft PR. Every other job needs `changes` (lint, site and
  site-agent since job 308, which landed first), so it skips with it. AGENTS.md (CLAUDE.md) and `docs/CI.md` now say `gh pr create --draft`, and push-pr.sh
  marks a draft ready after its push.
- **Tests.** `scripts/landing-test.sh` has new cases: a failing check pushes nothing,
  `PUSH_PR_SKIP_CHECKS=1` pushes, and a draft is marked ready after the push and on a rerun with
  nothing to push. The new `scripts/push-checks-test.sh` checks which checks run for 13 sets of
  changed paths. The lint gate runs both.

## Evidence (real runs)

**Why the push checks.** In the week to 18 November, 29 of 49 failed PR runs failed in the lint or
flutter job. Of the 28 failed job logs still readable, these checks catch 20:

- 8 schema checks (7 deleted a migration that is on main, 1 was out of order)
- 3 shellcheck, 2 TS pack, 1 e2e tsc and 1 old product name
- 2 format, 1 l10n and 2 lockfiles

The other 8 were tests: 6 flutter tests and 2 of the lint gate's script tests.

**Speed of the checks on hz.**

- This branch, with no app changes: lint.sh, actionlint and shellcheck took 35.7 s and passed.
- `flutter.sh --no-tests` on a clean app took 10.4 s, so a branch that changes the app takes about
  46 s.
- The full lint gate took 2 min 20 s and the full flutter gate 3 min 18 s. CI reports a failure
  only after a run of about 20 minutes.

**Planted slips.** A commit with four of last week's real failure kinds (a format slip in
`app/lib/app/app.dart`, an unused shell function, a deleted main migration, an async function
without `await` in e2e) failed in 40 s with
`push-checks: failed: lint.sh shellcheck typescript-pack flutter`. Each output named the file and
the fix.

**Cancelled runs, before.** 138 PR runs were cancelled from 11 to 18 November, using 2,909
runner-minutes. Every one was superseded by a run on a newer commit of the same branch.

| Kind | Runs | Median run | Runner-min |
| --- | ---: | ---: | ---: |
| first run of a PR, same tree as push-pr.sh's squash | 43 | 0.28 min | 165 |
| first run of a PR, squash rebased or added a fix | 19 | 0.6 min | 200 |
| fix round pushed while the previous run was going | 65 | 9.7 min | 2,493 |
| same tree re-pushed after a description edit | 6 | 0.4 min | 51 |
| commits no longer on GitHub | 5 | | |

**Cancelled runs, after.** #545 was opened as a draft, and its opening run 44342467552 skipped all
20 jobs in 2 s, using no runner. The 62 first runs a week go away once PRs are opened with
`--draft`. The 65 fix rounds are correct cancellations of superseded code. The push checks remove
the share of them caused by lint or format slips.

**OC3a: the flake was already fixed.** A subagent read the e2e job logs of every CI and on-demand
e2e run from 8 to 18 November (996 runs, about 2,175 e2e jobs).

- **Before.** The test failed 12 times, every time the same hang: the SDK's tokenless first POST
  got no answer. The stack logs of run 43566202026 show `user body write aborted` and Kong's 499.
  #440 (`f80960a7`, 14 November 10:46 UTC) fixed it at the root: `withTelemetry` now reads an
  unread request body before it answers.
- **After.** The last failure was 06:31 UTC that day. Since #440 the test passed in all 325 CI runs
  scanned. At the old 3.6 % rate, the chance of 0 failures in 325 runs is about 1 in 150,000.
- **Locally.** On hz the spec passed 24 of 24 (`--repeat-each=3`) on stack 607xx.

## Review 0 (in-session, FIX), fixed

1. merge-pr.sh waited its 30 minutes on a skipped `ci-ok` (a draft marked ready without a push).
   It now stops at once and asks for a new commit. There's a landing-test case for this; with
   main's merge-pr.sh it fails.
2. Untracked files fooled format, analyze and tsc, which read the directory while CI reads the
   commit. `flutter` and `e2e-tsc` now fail on untracked files in `app/` or `e2e/` and name them.
3. A failed `npm ci` in the TS-pack check went unnoticed. Its steps are now chained.
4. A change to a `deno.json`, `package.json` or `tsconfig` now also runs the TS pack.
5. push-checks.sh's run path is tested now, with stubbed lint and flutter gates: a failing check
   is named, and an untracked file is refused. Breaking the failure collection makes 5 cases fail,
   and dropping the untracked guard makes 2 fail.

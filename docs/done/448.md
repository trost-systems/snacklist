# Job 448: regression tests on the list, offline sync, add sheet and entitlements

Tests only. No change under `app/lib`, `supabase/` or any flag. New: seven test files (66 tests) and
`tool/mutate/mutate.py`, which found what to test and proves each new test fails when the logic it
pins breaks.

## How the gaps were found

The hot paths were already well tested (1,658 tests in `test/list` and `test/purchases`; line
coverage of `model.dart` 96 %, `list_cubit.dart` 98 %, `add_sheet_cubit.dart` 98 %), so more tests
of the same lines would add little. Instead `tool/mutate/mutate.py run tool/mutate/hotpaths.tsv`
flipped one operator at a time (`==`/`!=`, `&&`/`||`, `any`/`every`, `isEmpty`, `true`/`false`, ...)
in each range and ran that range's tests against every mutant:

### Review 0: the add sheet's numbers were false

The first report said the add sheet cubit and the ranking survived nothing. The reviewer found why:
`add_sheet_catalog_test.dart` and the two `suggest_*` tests read `../supabase/tests/suggest_parity.json`,
and the tool's copies held only `app/`, so every mutant whose tests included them failed to load and
counted as killed. Its baseline ran in the real `app/`, so it did not see it. `mutate.py` now makes
each copy a sibling layout (`app/` copied, the rest of the repo linked beside it) and runs the
baseline in a copy. The four ranges were run again with it (the table above has the new numbers).
The other ranges' tests read nothing outside `app/`, so their results stand.

## The new tests

`app/test/list/offline_replay_test.dart`, the queue (brief item 2):
- Every op queued behind an offline add that the server folds into the partner's open item
  (`put_item`, job 64b) moves to that item (`ontoKept`): ticks, edits, moves, claims, "Nein, nur
  abgehakt", typed prices. A delete and an undone delete's price are dropped; a placement next to
  the copy goes next to the kept item; a merge of the copy merges the kept item, and one of the two
  into each other is dropped. Ops of other items are untouched.
- A queued "Nein, nur abgehakt" (`DeclineShop`) survives the device queue's JSON.
- An untick clears when and by whom the item was bought; a tick keeps who until the server says.
- Through the cubit: offline, place the add first, or place another item next to it; the partner
  adds the same; on reconnect the placement goes to the partner's item and nothing is sent for the
  dropped copy. A tick and its decline queued offline survive a restart and reach the partner's
  item in order.
- A merge whose kept item the partner deleted meanwhile moves nothing queued for that item onto the
  other one (the mutant sent the edit to Karotten).
- An answer after a resync showed the list asks for one more resync only when it brings a row the
  snapshot lacked (job 99's guard against a row from before a missed delete), not for a row it had.

`app/test/list/move_to_list_test.dart`, two lists (brief item 1): offline, a move onto a list where
the item is open among other items is refused at once and nothing is queued; a ticked twin there
does not block it; a ticked item may move onto a list where the same is open; claiming next to a
partner's claim tells `item_claimed` once.

The add sheet (brief item 3):
- `add_sheet_merge_test.dart`, the match row's merge: amounts add up, only a brand or details the
  item lacks are filled; an item ticked or gone meanwhile, or an amount too long, is refused with
  `MergeRefused` and nothing is sent.
- `suggest_entries_rules_test.dart`, the device's ranking (`suggestRows` on the bundled catalog and a
  hand-made history): a name starting with the text before one holding it, however recent, and the
  closer of two holding it first; one brand row per brand, in the spelling bought last, in either
  history order; the household's spelling of a catalog brand first; a detail ranked by its latest
  purchase; sizes offer their neighbours from 1 to 8.
- `add_sheet_cubit_test.dart`, the sheet's state without widgets: a sheet just opened carries
  nothing and loads nothing; older rows never answer newer text, and a cached text is its own; Enter
  while loading takes nothing once the text moved on; a failed load is asked again; offline rows
  name a usual once; a late answer with stable rows is cached for its own text; a close that
  settles after the sheet opened again leaves it open; the details card shows only with its flag
  and saves a rename; a match row's tick is the add sheet's (no trip question), returns true, and a
  stale row is refused; match rows follow the list while typing but not while the sheet closes;
  picking a store or category keeps the rows carried, the request pending and the note on the
  match just taken; the device's ranking counts what the list bought since the index was read,
  back a year; the duplicate hint goes to an open sheet only, leaves only when that hint does, and a
  hand-over to the list is not counted as ignored while a later hint typed past is.

`app/test/purchases/account_lifetime_test.dart` and `unlocks_test.dart` (brief item 4, the existing
`FakeEntitlementsSource` seam, no change to payments code): whose Lifetime it is (own purchase or
beta grant yes; the household's purchase or tester grant, an own grant that ends, a yearly plan or
another member's purchase no; unknown is no, but no refund prompt either); the household's purchase
alone counts as paid; testers next to a purchase; one renewing plan of two still bills; an ended
plan bills no more; on an equal end the yearly plan names premium; the next end is the earliest;
offline answers no to paid, twice and billed.

Add, tick and undo (brief item 1) are the op variants and the queue above; category grouping is the
last row of the table.

```
cd app && flutter test test/list test/purchases test/analytics      # 2151 passed, 78 skipped (rebased on 4a3ceecba)

```

Both modes run in copies of `app/` beside links to the rest of the repo, first unmutated (a test
that fails there stops the run, so a missing file or a red test cannot read as a kill), with CI's
Flutter (`FLUTTER_DIR`, else `~/flutter-<FLUTTER_VERSION>`). A mutant that hangs (the queue never
dropping an acknowledged op loops) is TIMEOUT after `MUTATE_TIMEOUT` seconds (300), its whole
process group killed. The mutation evidence (every run's rows) is in the job directory,
`mut/*.tsv`.

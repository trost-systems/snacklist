- **Flag:** `input-stable-rows` (PostHog). It is in `app/lib/analytics/flags.dart` and in `releases/flags.json` with `"rollout": "off"`. Nobody has it on.

  - To see the change on TestFlight, the lead turns the flag on in PostHog for Peter's install, or for internal testers only, and keeps it off for everyone else.

## What was fixed (flag on)

- **Gap 1: rows under the finger.**
  - The typed row is rebuilt from the field's text on every key, so a tap never adds an older text ("M" while the field says "Milch").
  - Rows are keyed by content.
  - While a finger is on a suggestion row, no row changes. The tap adds the row as it was shown.
  - Code: `app/lib/list/add_sheet/add_sheet.dart` (a per-row `Listener` and the held rows in `_ContentState`) and `add_sheet_cubit.dart`.
- **Gap 2: local rows on every key.**
  - The device's rows (the typed line plus the matching usuals) show in the same frame as the key.
  - The server's answer is merged without moving them (`mergeRows` in `add_sheet/suggestion.dart`). The typed row takes the server's category and store, shown rows keep their order and text, and the server's other rows are appended up to 8 rows.
  - Stale answers are still dropped, now with tests.
- **Gap 5: on-device category.**
  - `app/lib/list/category_guess.dart` uses the household's own category for the same name first, then the generated lexicon. `supabase/classifier/client_lexicon.sh` now writes each form's seed key into `lexicon_forms.dart`.
  - The guess agrees with the server on 1617 of 1617 dictionary terms and 344 of 345 sweep items. These numbers come from a unit test, not from a phone.
  - The server still classifies on insert.
- **ST1: a new grocery's usual store.**
  - A grocery with no remembered store goes to the store the household's store memory names most for its category (`public.category_usual_store`).
  - `suggest_entries`, `parse_item` and `put_item` accept `p_category_store default false`, and the app sends `true` only with the flag on.
  - Corrections win, in this order: the item's own memory, then a later edit, then "Ohne Laden". The new table `item_store_cleared` records "Ohne Laden"; it is trigger-written, with a members-only read policy.
  - The automatic default is never learned as the item's store at add time.
  - Migration: `supabase/migrations/20261115205907_category_usual_store.sql`.
- **The duplicate note survives.** A device-read line with an open item's words ("Weihenstephan Milch" with Milch/Weihenstephan open) still says it is on the list.
- **No visual change.** There is no indicator, dimming or reserved slot; that is job 273. The category chip can show the device's guess before the server answers. That is the chip's existing look with earlier content.

## How the tests cover it

- **The "Milch" race.** In `app/test/list/add_sheet_stable_test.dart`, "Milch" is typed faster than the 120 ms debounce, with the server held back.
  - Flag on: the typed row equals the field after every key, and a tap adds "Milch".
  - Flag off: the row stays "M" and a tap adds "M", which pins the old behavior.
- **Press-freeze.**
  - A finger down on a row while the answer arrives: the rows stay, and the tap adds the shown row. After the finger lifts, the answer shows.
  - A finger on a chip holds nothing.
  - Removing the hold fails both tests (mutant run).
- **Stale reply.** An older text's answer arriving last never replaces the newer rows, with the flag on and off.
- **Merge pinned in the cubit.** An answer in another order keeps the shown rows. Bypassing `mergeRows` fails it.
- **Offline sort.** Flag on, an offline "Milch" sorts into Kühlregal at once. Flag off, it waits unsorted.
- **ST1.** `supabase/tests/category_usual_store.test.sql` has 47 pgTAP cases:
  - the default;
  - item memory, a later edit and "Ohne Laden" winning, including undo, an add with "Ohne Laden", `parse_item`, and store deletion;
  - no learning of the default;
  - another household;
  - the flag-off calls equal the old ones.

  `rls.test.sql` has the new table's cross-household case. `list_repository_test.dart` pins the params with the flag off and on.
- **Driven on the web release build** with `.cursor/skills/verify-snacklist/journeys/input-stable-rows.mjs`. The server's answers and writes were held back 2.5 s, and "Kefir" was typed a key every 30 ms.
  - Flag off reproduced the bug: the typed row read "K", the tap added "K", and it waited unsorted.
  - Flag on: the row read "Kefir", Kefir showed under Kühlregal before the server had it, and it landed at "Wochenmarkt", the store set up for the household's other chilled items.
  - A finger held on a row kept the rows while the answer arrived. The control without a finger showed the same answer appending three rows below.
  - Screenshots are in `docs/screenshots/272/` and in the PR.

## Dev-only timing log

- **Where:** `_AddSheetState._timeRows` in `app/lib/list/add_sheet/add_sheet.dart`.
- **When it runs:** only when `kDebugMode` is on, through `debugPrint`. Release builds and analytics never see it, and it logs the text's length, never the text.
- **Format:**
  ```
  [add-sheet timing] stable=on len=5 rows 57 ms
  [add-sheet timing] stable=on len=5 answer 95 ms
  ```
  - `rows` is the time from the key to the first frame with that text's rows.
  - `answer` is the time to the frame showing the server's rows.
  - `cached` means the rows were already the answer.
- **How to read it:** run a debug build on a phone (`flutter run`), flip the flag, type, and grep `[add-sheet timing]`. With the flag off it gives the baseline.
- **Not a device measurement:** the numbers above are from widget tests on the fake clock. No device was measured in this job.

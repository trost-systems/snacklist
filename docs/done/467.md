# Job 467: native Siri App Shortcuts not recognised on TestFlight

On TestFlight 1541 (English Siri), "Add milk to Snacklist" got "Snacklist hasn't added support
for that with Siri", and "What's on my Snacklist?" got a question whether to turn on Snacklist's
shortcuts.

## Root cause

The release build was not the problem. The signed IPA of run 531 and an unsigned release archive
built for this job both carry the three App Shortcuts, the de/en phrase sets and a trained phrase
model per language (`<lang>.lproj/nlu.appintents/nlu.lzfse`), the same as a debug build.

Siri gives those two answers while an app's Siri switch is off (developer forum reports; Apple
documents neither). The app asked for "Use with Siri" only when it stored a new Siri credential
after sign-in. An install that kept its credential, whose credential call failed, or that missed
the alert was never asked again. Until the user answers, SiriKit's Lists fallback routes nothing to
the app. That the "Turn on shortcuts" question sets the same switch is inferred; the retest checks
it.

## Fix

- `AppDelegate.swift`: on every `UIApplication.didBecomeActiveNotification` the app asks
  `INPreferences.requestSiriAuthorization` while the status is `.notDetermined`, from the first
  launch. iOS shows the question once. `SiriAuthorization` in `SiriBridge.swift`; storing a
  credential still asks.

## Checks

- `scripts/siri-target.py` and `scripts/siri-target-test.py` (lint gate): the Siri Swift, with the
  `AppShortcutsProvider`, in the Runner target's Sources; `AppShortcuts.xcstrings` and
  `Localizable.xcstrings` in its Resources; no provider in another target.
- `scripts/siri-phrases.ts`: no phrase spells the app's name.
- `scripts/app-shortcuts-bundle.py` (ios gate, Fastfile IPA): the de and en phrase model.
- RunnerTests `SiriAuthorizationTests`: the became-active notification asks only while unanswered.

## Device retest (Peter)

On the first TestFlight build that contains this PR, not 1541: `docs/NEEDS_PETER.md`, "Job 467".
If Siri still behaves as on 1541, delete the app and install that build again.

Setup: install the new TestFlight build; open Snacklist; sign in; open the list once; background
the app. If iOS asks to allow Siri or to turn on shortcuts for Snacklist, allow it. Settings › Apps
› Snacklist › Siri: **Use with Siri** and **Learn from this App** on (DE: **Mit Siri verwenden**,
**Von dieser App lernen**). Settings › Siri › Siri Responses › **Always Show Speech**. Shortcuts
app: the Snacklist tile lists **Add to Snacklist**, **Read my Snacklist**, **Open Snacklist** (DE:
**Zu Snacklist hinzufügen**, **Meine Snacklist vorlesen**, **Snacklist öffnen**). Siri language
English (United States) first, then Deutsch (Deutschland).

English:

- "Add to Snacklist" or "Add something to my Snacklist" → Siri asks what to add → "milk" → "Added
  milk to Snacklist."
- "What's on my Snacklist?" → Siri reads the open items, without asking to turn on shortcuts.
- "Show my Snacklist" → the app opens on the list.
- "Add milk to Snacklist" → adds in one sentence (App Shortcut if milk was suggested, otherwise
  SiriKit Lists), never "Snacklist hasn't added support for that with Siri."

Deutsch: „Füge etwas zu meiner Snacklist hinzu“ (then „Milch“), „Was steht auf meiner Snacklist?“,
„Zeig meine Snacklist“, „Füge Milch zu Snacklist hinzu“. Same expectations; no „unterstützt das
nicht“, no question to turn on shortcuts.

If the first two work but a brand-new name in "Add X to Snacklist" fails, that is the
item-suggestion limit, not this bug; note whether SiriKit then adds it.

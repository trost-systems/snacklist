# Job 466: test installs send no analytics (2026-11-26)

What changed:

- `app/lib/analytics/internal.dart`: `isTestAccount(email, providers)`. True for an e-mail on a
  reserved test domain (`fg-test.invalid`, `fg.test`, `example.test`, the other reserved ones)
  or a Google-only account matching `^[a-z]+[a-z]+\.[0-9]{5}@gmail\.com$` after trim and
  lower-case (Play pre-launch, the DEL-G1 pattern). `isInternal` counts it too.
- `app/lib/analytics/analytics.dart`: in a release build, a signed-in test account stops the
  PostHog SDK (no events, error reports, native crash reports or install-id flag requests) and
  gets the shared flags. The stored answer and install id stay; signing out starts nothing, the
  next signed-in user who is not a test account restarts the SDK. A test account's answer is not
  recorded on the server. Debug and profile builds still send, marked `is_internal`.
- Review 0 fix: `main.dart` passes the restored auth user to `startAnalytics(user:)`, so a
  stored yes on a test account's install starts no SDK at the next launch either (before, each
  cold start made one `/flags/` request with a fresh id until the session caught up). Unit test
  "a stored yes and a restored test account", and the e2e spec now reloads.
- `app/lib/session/session_cubit.dart`: `AnalyticsUser` carries the sign-in providers
  (`app_metadata.providers`). The e-mail never leaves the device.
- Review 1 fix: after a test account signs out, the SDK stays off (also at a signed-out cold
  start) until a real user signs in; a test account's consent is no longer recorded on the
  server. Unit tests for both, the e2e spec signs out and reloads, and a table proves the tester
  group `internal`, `ANALYTICS_INTERNAL_HOUSEHOLDS` and the RevenueCat tester household still
  send in a release build.
- e2e: `newEmail` now uses `e2e.snacklist.app`, listed in `ANALYTICS_INTERNAL_EMAIL_DOMAINS` in
  `app/config/e2e.json`, so the specs keep sending. New spec "a test account sends nothing after
  a yes" with `testAccountEmail` (`example.test`).
- Docs: `docs/ANALYTICS.md` "Test accounts send nothing", `docs/DECISIONS.md` job 466, feature
  `privacy-consent` sub-feature `test-account`.

How to verify: `flutter test test/analytics` (table-driven cases in `internal_test.dart`, the
cubit cases in `analytics_test.dart` "a test account sends nothing in a release build"), and the
e2e spec in `e2e/tests/analytics.spec.ts`.

Not changed: `supabase/functions`, legal and privacy texts, the consent answer, event properties.
Ships with the next green main build to TestFlight and Play internal; no flag.
